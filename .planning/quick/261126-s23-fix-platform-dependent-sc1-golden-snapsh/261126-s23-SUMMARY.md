# Phase quick Plan 261126-s23: Fix platform-dependent SC1 golden snapshot tests Summary

Replaced five exact-equality comparisons of search results against the SC1 golden snapshot with a recursive helper that tolerates one-ULP float drift, unblocking the ubuntu CI cells without weakening ranking, ordering, or id assertions.

## Objective

Test Matrix run 45815417974 on commit 6044311 was red on all four ubuntu cells and green on all four macOS cells. Root cause: SQLite FTS5's `bm25()` calls the platform libm's `log()`, and the libm result differs by one ULP between macOS and ubuntu. The only observed diff was `bm25_score` `1.313431110717347e-06` (macOS) versus `1.3134311107173473e-06` (ubuntu); ranking, order, and every other field were identical. Five assertions compared the full result list to `TestHybridSC1PipelineGolden.SNAPSHOT` with `==` and were therefore platform-fragile.

## What Was Built

- Added module-level `_assert_matches_snapshot(actual: object, expected: object) -> None` immediately after the import block, before the Fixtures section:
  - both floats → `pytest.approx(expected, rel=1e-12)`
  - both dicts → exact key-set equality, then recurse per key
  - both lists → exact length equality, then recurse pairwise in order (`zip(..., strict=True)`)
  - otherwise → exact `==` (ints, strings, `None`, bools, type mismatches)
  - Asserts rather than returns, so failures stay inside pytest's reporting; docstring explains the libm/ULP rationale.
- Routed the five snapshot sites through the helper, changing nothing else:
  - `TestHybridSC1PipelineGolden.test_default_options_match_prechange_snapshot`
  - `TestHybridSC1PipelineGolden.test_explicit_default_weights_match_prechange_snapshot`
  - `TestCandidateFetch.test_candidate_fetch_off_path_matches_sc1_snapshot`
  - `TestSearchPipelineIdentity.test_protocol_only_embedder_keeps_the_plain_embed_path`
  - `TestSearchPipelineIdentity.test_default_no_prompt_query_role_reproduces_the_sc1_golden`

No `src/` code and no `SNAPSHOT` constant values were touched.
