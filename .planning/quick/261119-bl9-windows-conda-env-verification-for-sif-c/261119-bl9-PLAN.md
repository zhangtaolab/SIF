<objective>
Verify SIF on Windows in the three conda environments `dnallm-cpu`, `dnallm-cuda`, and `dnallm-xpu`, with CUDA and Intel XPU as the focus, and close the XPU gap that verification exposes: SIF's embedding backends currently auto-select only CUDA, MPS, or CPU.

Purpose: give the user a factual dependency and runnability matrix for the three envs, and make Intel XPU a first-class auto-detected backend instead of silently falling back to CPU on an XPU host.

Output: a per-env machine-facts report, one typed device-selection helper with XPU support and model-free tests, updated generator-owned and manual device documentation, and a post-change re-verification of all three envs.

Scope boundaries (locked):
- Do NOT upgrade or replace `torch`, `torchvision`, or `torchaudio` in any env. The `+cpu`, `+cu130`, and `+xpu` builds are the env's vendor stack; a proposed torch change is a stop-and-report condition, never an install.
- Do NOT change `pyproject.toml` or `uv.lock`.
- Do NOT add a user-facing device setting or CLI flag. The shipped contract is automatic detection plus an explicit `device=` constructor argument; docs/configuration.md states SIF exposes no device setting.
- Env mutation is limited to the repo editable install and the declared dependencies that are missing or below their declared floor. That permits the recorded `mcp` 1.30.0 -> 2.3.0 and `modelscope` 1.34.0 -> 1.40.3 upgrades (both dry-runs are additive) and forbids every other change. Any unexpected pip delta or `pip check` failure is reported, not repaired.
- Do NOT refactor unrelated code, tests, or docs. The only permitted source change is the XPU device-selection gap and its tests/docs.
- Do NOT download embedding models. The offline embed smoke uses only the already-cached `microsoft/DialoGPT-small` snapshot and is diagnostic, not a gate.
- Conda-env pytest runs MUST use `--no-cov`: the repo addopts force `fail_under=90`, which a scoped run structurally cannot satisfy (WINDOWS.md ledger item 8).
- `scripts/windows_smoke.py` refuses a dirty tree, so it runs after provisioning and before any Task 2 source edit.
