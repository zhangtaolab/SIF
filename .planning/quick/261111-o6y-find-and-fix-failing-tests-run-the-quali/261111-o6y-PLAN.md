<objective>
Make the pytest suite hermetic against ambient color environment variables. With FORCE_COLOR=1, 60 tests across 11 files fail because Rich-rendered CLI output contains ANSI escapes that break plain-text substring assertions (full list: .planning/quick/261111-o6y-find-and-fix-failing-tests-run-the-quali/261111-o6y-evidence-force-color-failures.txt). With color vars unset the suite is green (1512 passed, 1 skipped, coverage 95.02% >= 90% gate).

CRITICAL mechanism finding (planning-time probe — do NOT "simplify" this plan to a fixture-only fix): a per-test env-scrub fixture ALONE is insufficient. Every sif.cli module builds `console = Console()` at module import time (16 sites: src/sif/cli/main.py:23 plus src/sif/cli/commands/*.py). Rich 15.0.0 caches `_color_system` in Console.__init__ (rich/console.py ~707-712), and `_render_buffer` (rich/console.py:2132) renders styled segments whenever that cached `_color_system` is non-None — `not_terminal` only suppresses control segments. Probe-verified: a console constructed under FORCE_COLOR=1 still emits ANSI after the env is scrubbed (is_terminal=False, output still styled). Therefore the scrub MUST run before the first sif.cli import, i.e. at tests/conftest.py import time. The autouse fixture is the second layer (per-test guarantees for Click's dynamic reads and subprocess child envs), not the load-bearing piece.

Purpose: the suite passes deterministically regardless of ambient color env, reproducing the known-green baseline (all color vars unset) — test-side only, zero src/ changes.
Output: centralized color-env isolation in tests/conftest.py (import-time scrub + autouse fixture) and a small regression file pinning both properties, with red-to-green evidence and dual-regime full-suite gates.
</objective>
