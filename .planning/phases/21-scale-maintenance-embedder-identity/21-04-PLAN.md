<objective>
Enforce the persisted identity at every vector-touching search boundary: search paths warn once and mark results (or fail with a remedy when vector search is impossible), and every query-side embed routes through the query role.

Purpose: EMB-01's public contract is the same-dimension swap protection the milestone is built around. This plan makes the identity observable where users and agents hit it, without adding a result field, changing the schema, or touching BM25-only commands. EMB-02's role boundary reaches its query consumers here: the hybrid/`vec:`/Hyde legs, expansion, vsearch, and the bench/eval query legs.
Output: pipeline identity checks, CLI/MCP/bench/eval policy, and role-aware query call sites.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored identity -> search boundary | A different embedder may be paired with existing vectors |
| query text -> embedding backend | A query prompt must never be applied to document text (or vice versa) |
| legacy index -> assumed identity | An index without provenance is assigned the current identity at a schema-opening host |
| MCP client -> vector search | Agents consume results that may be marked stale |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-11 | Tampering | vector-space mismatch on search | high | mitigate | Field-wise identity check at every vector-touching exit; same-dim mismatch warns once and marks all results stale; dimension mismatch degrades or fails with a remedy (Tasks 1-2). |
| T-21-12 | Spoofing | legacy assumed identity | medium | accept | An index predating identity is assumed correct; search is never blocked, a later swap is still detected against the assumed value, and `--force` is the certification path. Residual risk documented. |
| T-21-13 | Denial of Service | warning amplification | low | mitigate | A module-level latch emits one warning per process per identity pair; per-result warnings are forbidden (Task 1). |
| T-21-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install occurs in this phase; the legitimacy gate is a no-op. |

## Residual Risk

An assumed identity keeps `pooling`/`revision` unknown until a full `--force` re-embed certifies it, leaving a permanent blind spot for same-name model changes during that window. This is the locked D-04 tradeoff: the remedy is explicit and search is never blocked. Accepted.
</threat_model>
