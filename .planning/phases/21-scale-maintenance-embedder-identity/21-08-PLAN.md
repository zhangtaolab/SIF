<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model settings -> dimension guard | The loaded model's width is compared with the stored vec0 width |
| legacy index -> assumed identity | An index without provenance is assigned the current identity |
| settings prompt scheme -> embedder construction | A host may record a prompt scheme it never applies |
| model metadata -> OpenAI endpoint dimension check | Endpoint detection and SIF_EMBEDDING_DIM can disagree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-26 | Spoofing | legacy assumed identity at schema open | medium | accept | An index predating identity is assumed correct; search is never blocked, a later swap is still detected against the assumed value, and `--force` is the certification path (Task 1). |
| T-21-27 | Repudiation | dimension-guard error wording | low | mitigate | The identity module owns the shared read and wording; the schema and OpenAI messages are pinned byte-identical, so users can tell which model and width disagree (Tasks 1-2). |
| T-21-28 | Tampering | prompt scheme recorded but not applied | medium | mitigate | The MCP backend resolves one scheme and uses it for both the identity and `factory.create_model`; a test asserts the factory receives both prompt names (Task 2). |
| T-21-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install occurs in this phase; the legitimacy gate is a no-op. |

## Residual Risk

An assumed identity keeps `pooling`/`revision` unknown until a full `--force` re-embed certifies it, leaving a permanent blind spot for same-name model changes during that window. This is the locked D-04 tradeoff: the remedy is explicit and search is never blocked. Accepted.
</threat_model>
