<objective>
Replace the hand-rolled MCP protocol shell with the official SDK v2 composition root and prove it tracer-first: `status` served end-to-end over stdio and HTTP, dual-era wire transcripts locked, transport security verified before deletion, and the watch host composed under the SDK lifespan.

Purpose: MCP-01 is the phase's riskiest seam. The dependency gate (D-02) already passed in research, but the install, the 3.10 floor, the era matrix, and the old-shell deletion must be re-proven in-repo before any other tool moves. D-01 forbids a dual stack; this plan deletes the old shell only after the new one carries a tool through both transports.
Output: the `mcp` dependency, `src/sif/mcp/app.py` and `tools.py`, a lazy-backend skeleton, the composed watch lifespan, five era goldens, SDK-client and transport-security tests, and the deleted old shell.

<assumption_delta_decision>
- **noun:** tool result channel (legacy compact JSON text + modern `structuredContent`).
- **decision:** `add-alongside`.
- **rationale:** the compact JSON text channel is a locked backward-compatibility contract for 2024/2025-era clients (D-05), and structured output is strictly additive (D-10). Collapsing to one channel would either break legacy parsers or drop citation-grade structure.
- **accepted debt:** the two channels must always be derived from the same Pydantic output model; a divergent hand-written structured payload is forbidden.
- **what would force a later promote:** a future era deprecating text content, or an SDK auto-wrap that reproduces legacy compact text exactly.
- **invariant test:** every tool's text payload must parse to a mapping deep-equal to `structured_content`; this plan pins it for `status`, and 22-02 extends it to all seven tools.
</assumption_delta_decision>
