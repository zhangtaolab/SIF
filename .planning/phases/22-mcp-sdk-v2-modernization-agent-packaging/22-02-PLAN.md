## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> tool input | Untrusted query strings, filter/match ASTs, collections, and document identifiers |
| tool annotations -> host approval UX | A false read-only claim could cause a host to auto-run a write |
| tool description -> agent planning | Overclaims mislead the model about reranking and approvals |
| backend -> search layer | lex/vec direct paths bypass the hybrid pipeline |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-22-05 | Elevation of Privilege | tool annotations | high | mitigate | Only read-only tools are registered; every annotation is `read_only_hint=True`/`open_world_hint=False`; honesty test enumerates them; future write tools require `read_only_hint=False` + `destructive_hint=True` (Task 3). |
| T-22-06 | Tampering / Information Disclosure | tool input and error boundary | high | mitigate | Shared `parse_filter`/`parse_match` validation, preserved Pydantic coercion, `ToolError` with remediation text, SDK sanitization of unexpected exceptions; no `INVALID_PARAMS` for tool semantics and no internal detail in error text (Tasks 1-2). |
| T-22-18 | Tampering | lex/vec filters | medium | mitigate | Both direct paths use the shared parameterized filter AST through `SearchOptions.filter`; no SQL string interpolation (Task 2). |
| T-22-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install in this plan; dependency gate already covered by 22-01. |
