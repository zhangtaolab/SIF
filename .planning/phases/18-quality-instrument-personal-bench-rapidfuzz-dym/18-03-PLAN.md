<objective>
Turn the personal bench into a comparison instrument: versioned saved runs under the cache directory, a `--compare` entry point that re-runs the saved query set against the current engine, and a paired-bootstrap noise gate that refuses to call a winner inside noise. Replay becomes a stability measurement against the saved snapshot.

Purpose: EVAL-02's contract is only real when two arms answer the same queries over the same corpus. This plan makes pairing structural (saved query set + fingerprint match), makes small-N honest (CI + 1/N + suppression), and produces the evidence Phase 19, 23, and 24 will cite.
Decision coverage: implements CONTEXT D-07 (paired 95% bootstrap CI + mean delta >= 0.01, 1/N floor), D-10 (auto-save query/path/split/leg/language/grade, never content; `--no-save`), and D-12 (`--compare <saved-run.json>`, corpus-fingerprint refusal, versioned saved-run format).
Output: `--compare`/`--no-save`, the saved-run schema and validation, the bootstrap gate, comparison rendering, and the personal-bench narrative in `docs/benchmarking.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saved-run JSON -> comparison engine | A local file the user points at is untrusted input (types, sizes, version, values). |
| saved paths -> filesystem | Retrieved/target paths are comparison keys, never opened. |
| current index -> comparison | A different corpus behind the same path would manufacture a delta. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-07 | Tampering / Denial of Service | `load_saved_run` / `validate_saved_run` | high | mitigate | Enforce a 5 MB file cap and 10,000-record cap; require `version == 1`; type/range/enum-check every field; reject non-finite floats and bool-as-int; translate all defects to ClickException with the field named. |
| T-18-08 | Information Disclosure | saved `target_path`/`retrieved` paths | medium | mitigate | Treat paths as opaque comparison keys; resolve target paths with a parameterized `documents` lookup only; never `open()` a saved path; never store content/snippets. |
| T-18-09 | Spoofing / Integrity | corpus fingerprint match | high | mitigate | Recompute the fingerprint from the current DB and refuse the comparison on mismatch, naming both values; the saved fingerprint is never trusted as the current value. |
| T-18-10 | Repudiation / Transparency | noise gate | high | mitigate | Winner requires a CI excluding zero AND a rounded mean delta >= 0.01; report N, 1/N, and helped/hurt/unchanged; held-out alone can warrant a change. |
| T-18-SC | Tampering | dependency installs | high | mitigate | This plan installs no package. rapidfuzz is gated by the Plan 04 blocking checkpoint. |

**Residual risk:** the comparison is only as honest as the saved run's `retrieved` lists; the schema stores paths in rank order and the baseline recompute uses exactly those lists.
</threat_model>
