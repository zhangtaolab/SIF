<objective>
Expand the proven tracer into the full personal query set and its bias controls: add the body-snippet leg with a per-leg paraphrase overlap budget, classify every known-item query by language and length, split deterministically into tuning/held-out, report every leg x language x bucket with small-group suppression, and add the query_log replay leg with its documented CLI-only bias.

Purpose: EVAL-02 is the trust layer. A personal bench whose queries leak the target text, whose groups hide small N, or whose replay is sold as quality is worse than no bench. This plan makes each bias visible and test-pinned before any comparison contract is built on top.
Decision coverage: implements CONTEXT D-01 (body and replay legs complete the three-leg default), D-02 (replay measures stability, not quality; CLI-only bias documented), D-05 (per-leg budget: title exact-term, body Jaccard <=0.60, replay not synthesized), D-06 (sha256 50/50 split; held-out >=25 by widening sampling), and D-08 (per-leg x language x length report; <10 suppression with names).
Output: an expanded `personal_bench.py` domain surface, the richer `sif eval --personal` report, and the EVAL-01/EVAL-02 unit battery.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQLite `query_log` -> replay leg | Locally stored queries are user content; they must not leak into reports beyond the query strings the user typed. |
| SQLite `documents` -> body synthesis | Body text is untrusted for markup and must be stripped before becoming a query/table cell. |
| report data -> CLI table | Query text and group names are user-derived and rendered through Rich markup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-04 | Information Disclosure | replay/report serialization | high | mitigate | Replay records store query text and top-k paths only; no document content, snippets, or result bodies. Tests assert no `content` key and no body text in output. |
| T-18-05 | Denial of Service | body synthesis / Jaccard / grouping | medium | mitigate | Cap body candidates at 10 tokens, cap replay at 500, cap synthesized queries at 500, and compute Jaccard on token sets in one pass; the whole-corpus pass stays metadata-only and content is loaded only for the sampled subset; no unbounded `fetchall()` of content. |
| T-18-06 | Spoofing | group names / query cells in Rich output | medium | mitigate | Truncate then `rich.markup.escape()` every query-derived and path-derived cell; group names are built from fixed enums, not user text. |
| T-18-SC | Tampering | dependency installs | high | mitigate | This plan installs no package. rapidfuzz is gated by the Plan 04 blocking checkpoint. |

**Residual risk:** replay has no click labels; the report says stability, not quality, and never gates a defaults decision on it.
</threat_model>
