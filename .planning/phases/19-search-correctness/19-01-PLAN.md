## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user file content -> parser -> canonical metadata JSON -> SQLite | Untrusted frontmatter keys and typed values cross into hash input and persisted JSON |
| parser extension dispatch -> filesystem | A file suffix selects a parser; the fallback path is chosen here |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-01 | Tampering | `canonical_metadata_json` / persisted `documents.metadata` | medium | mitigate | One canonical serializer used for both hash input and storage; `json.dumps` with `default=str` and string-coerced keys; metadata is bound as a SQL parameter, never interpolated; tests pin the typed-value round trip |
| T-19-02 | Denial of Service | `IncrementalIndexer._process_file` parser selection | low | mitigate | Unknown suffixes fall back to `TextParser` (bounded whole-file read already used by every parser); no recursive or external-format decoding is added |
| T-19-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install in this phase; the v1.2 dependency lock (only `mcp` and `rapidfuzz`) is unchanged and `uv.lock` is not modified |
</threat_model>
