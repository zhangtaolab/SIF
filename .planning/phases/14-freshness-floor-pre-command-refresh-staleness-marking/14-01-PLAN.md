<objective>
LIVE-10: the pre-command drift refresh floor. With no watch or daemon running, the CLI search trio (`sif search`, `sif vsearch`, `sif query`) stat-walks the collections being searched, detects drifted files (mtime vs the `documents` table), and — only when drift is under a file-count cap — refreshes them BM25-only via the Phase 12 `update_paths` seam under the Phase 11 flock before searching. A clean index pays a read-only walk with zero writes, zero locks, zero notices.

Purpose: "Always works even without watch" (SC1) at near-zero clean cost (SC2), doubling as the event-overflow backstop (D-03). The check lives in the CLI command layer so `sif bench` (Phase 16 latency) and the MCP server bypass it by construction (D-01).

Output: new `src/sif/indexing/drift.py`, a lightweight repository stat method, two `SIF_` settings, trio wiring with the stderr contract, deterministic drift/cap/coexistence tests, regenerated settings+CLI docs.

Mechanism note (research correction, SC1): SC1's "mtime/size check" is implemented **mtime-primary** — `documents.file_size` is frontmatter-stripped body byte length and is never refreshed on update (RESEARCH Pitfall 1), so a size compare would false-positive forever. The derivation intent (stat-based drift detection) is preserved exactly; document this in the drift helper's docstring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → drift walk | untrusted on-disk state (symlinked roots, unmounted collections, pathological trees) crosses into the drift detector |
| sif process → stderr/stdout pipes | notice/warning text crosses to user pipes consumed by `sif -q search ... --json` (project skills) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-01 | Tampering | drift.py walk (path confusion via symlinked roots, /tmp vs /private/tmp) | medium | mitigate | Resolve every walk path with `.resolve()` before compare (stored paths are resolved); walk stays scoped to registered collection roots via FileScanner.matches' `is_relative_to(root)` check |
| T-14-02 | DoS | drift.py walk on pathological trees | low | mitigate | Walk is one rglob+stat pass (~43 ms @ 5k files, locally probed); refresh work bounded by the file-count cap; the whole check disableable via SIF_SEARCH_REFRESH_ENABLED |
| T-14-03 | Information Disclosure | stderr notices / warnings | low | mitigate | Notices name counts and commands only — never document content, titles, or paths in user-facing notices beyond what search already prints; logging discipline unchanged (content never logged) |
| T-14-SC | Tampering | package installs | high | accept | Phase installs nothing — zero new runtime dependencies (locked decision; Package Legitimacy Audit in 14-RESEARCH.md is empty) |
</threat_model>
