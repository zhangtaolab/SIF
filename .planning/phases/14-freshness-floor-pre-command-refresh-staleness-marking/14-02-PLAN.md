<objective>
QUAL-06 core: the derived vector-staleness signal, computed in the shared result-assembly path so every search surface marks consistently. A result is stale when its document has no rows in `document_embeddings` (the corrected D-08 formula — RESEARCH Pitfall 3: BM25-only updates purge chunks AND embeddings, so "has chunks but no embeddings" never fires for the real lag state; "no embeddings" is the truthful derivation, same schema-free virtues). The boolean lands on `SearchResult.vectors_stale` and rides `to_dict()` into `--json` automatically; the MCP backend forwards it explicitly; `sif status` gains a Vector lag row.

Purpose: closes the Phase 12 tiered-depth deferral — vector lag becomes visible instead of a silent quality cliff, with zero schema change and zero new dependencies.

Output: new `src/sif/search/staleness.py`, `SearchResult.vectors_stale`, three searcher call-site edits, one MCP forwarding line, the status row, and a battery of new/extended tests including the D-08 invariant regression.

Display-gate decision (RESEARCH open question 2, resolved at plan time): markers activate only when the index has at least one embedding. Pure-BM25 users (who never opted into vectors) see no markers and no embed nagging; the moment embeddings exist, every lagging doc is marked. Tests must match this choice.
</objective>
