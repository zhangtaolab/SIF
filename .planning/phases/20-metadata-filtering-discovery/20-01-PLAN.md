    Condition nodes: `Eq`, `Ne`, `Gt`, `Gte`, `Lt`, `Lte`, `In`, `Nin`, `All`, `Contains`, `Prefix`, `Suffix`, `TypeCondition` (operator literal `type`), `Exists` — 14 condition classes; group nodes `And` and `Or` with `operands: list[FilterNode]` and `Not` with `operand: FilterNode`; `FilterNode = Annotated[Union[...all 17...], Field(discriminator="operator")]` with `model_rebuild()` on the three group models. `field` is `str` with `min_length=1, max_length=128`, validated to be ≤ 128 UTF-8 bytes.     Per-operator validators (raise `FilterValidationError` naming field and operator, with the AST path): `gt`/`gte`/`lt`/`lte` require a finite `int`/`float` that is not a `bool`; `type` requires exactly `"string"`, `"number"`, or `"boolean"`; `exists` requires a `bool`; `in`/`nin` require a non-empty homogeneous list of one scalar type (cap 128 elements); `all` requires a non-empty list; `eq`/`ne`/`contains`/`prefix`/`suffix` accept a scalar or (for `contains` only) a non-empty homogeneous list; text operands must be non-empty strings; `caseInsensitive` is accepted only when the value is a `str` or `list[str]`. Groups: `and`/`or` require 1-64 operands; `not` requires one operand.

    Budgets, enforced in the raw-dict pre-walk before pydantic: depth ≤ 8, nodes ≤ 64, string operand ≤ 1024 characters, array operand/list ≤ 128 elements; messages name the budget (e.g. `filter exceeds the maximum nesting depth of 8`). `field` byte length is checked after validation (128 bytes).

    `mtime` input normalization (D-12): in `parse_filter`, when `field == "mtime"` and the operand is a string, parse with `datetime.fromisoformat`, treat a date-only value as UTC midnight, treat a naive datetime as UTC, convert an aware datetime to UTC, and replace the operand with `int(epoch_seconds)`. Strings are rejected for ordering on every other field. Never rewrite the operand for a non-ordering operator on `mtime` (e.g. `exists`).

    `parse_match(payload) -> FilterNode`: same node classes and budgets, then reject any leaf whose `field` is not `"key"` or `"value"`, reject the `exists` and `all` operators with a message naming the restriction, and reject `gt`/`gte`/`lt`/`lte` on `field == "key"` (a key is text; ordering is never lexicographic — ordering on `field == "value"` stays allowed for numeric values).
