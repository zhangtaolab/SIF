<objective>
Expose the proven filter on the two public surfaces: the remaining two CLI commands and the MCP inputs, with one shared validator and the correct error taxonomy at each boundary.

Purpose: FILT-01's success criterion is that a user can filter *any* CLI search and *any* MCP query; FILT-02's is that built-in fields ride the same surface. The MCP schema shipped here is also the Phase 22 contract, so the field must be declared in the hand-written schema, not only in the pydantic model.
Output: `--filter` on `vsearch`/`query`, `filter` on the three MCP inputs with schema sync, the backend threading, the CLI/MCP error-path batteries, and regenerated CLI docs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell → CLI `--filter` | Untrusted JSON; must fail before any index work. |
| MCP client → tool handler | Untrusted `filter` dict; must be a recoverable tool error, not a protocol fault. |
| CLI/MCP → search legs | A dropped filter would widen results across scopes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-01 | Tampering | CLI/MCP filter parsing | critical | mitigate | Both surfaces call the one `parse_filter`; operands never touch SQL text (compiler is parameterized). Injection-shaped values are covered by 20-01/20-03 tests. |
| T-20-02 | Denial of service | MCP `filter` payload | high | mitigate | The shared budget pre-walk runs before pydantic on every surface; a hostile nested payload fails fast with a named budget message. |
| T-20-06 | Integrity | CLI output modes | medium | mitigate | No filter path writes to stdout; `--json` output is asserted to parse and contain no notice text. |
| T-20-07 | Information disclosure | input → options threading | high | mitigate | The parsed AST is passed explicitly to `SearchOptions.filter`; with no filter it stays `None`; tests assert identity through the backend and `None` on the unfiltered CLI paths. |
| T-20-SC | Tampering | package installs | high | mitigate | No dependency added; no install task in this plan. |
</threat_model>
