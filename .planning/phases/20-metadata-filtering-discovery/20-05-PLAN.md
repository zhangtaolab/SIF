    Return the frozen envelope: `documents` (integer — eligible documents in scope, collection predicate only), `filteredDocuments` (integer, present only when `filter_predicate` is not None — scope AND filter), `totalKeys` (integer), `remainingKeys` (integer), `skippedKeys` (integer), and `keys` (list). Each key entry is `{"key": str, "documents": int, "types": [...]}`; each type entry is `{"type": "string"|"number"|"boolean", "multiValued": bool, "documents": int, "distinctValues": int, "values": [{"value": ..., "documents": int}, ...], "remainingValues": int, "range": {"min": float, "median": float, "max": float} | absent}` — `range` only on the `number` type. These camelCase names are the deliberate mixed-casing contract (D-15); the dict is the wire shape, and the MCP pydantic models mirror it exactly.

    Region: one eligible-id CTE from `documents d` with the collection predicate and `filter_predicate`. Every aggregate joins `document_metadata_values mv` to that region. `match_predicate` narrows the reported entries (keys, types, values, distinct counts) but never the document denominators. Query budget: one query each for `documents`, `filteredDocuments` (when needed), `totalKeys`, the key window, `skippedKeys`; then at most two batched queries for the page's keys (type split with `COUNT(DISTINCT document_id)` and `MAX(ordinal) > 0`, and a values `GROUP BY key, value_type, text_value, number_value, boolean_value` with `HAVING COUNT(DISTINCT document_id) >= ?`), plus one median query for the numeric keys. Aggregate only the page's keys — never materialize the whole value space.

    Ordering: `sort="count"` orders keys `documents DESC, key ASC`; `sort="value"` orders `key ASC`. Values order `documents DESC`, then a stable string form of the value ascending. `min_count` filters value entries (and their counts) before windowing, so `distinctValues` is the post-`min_count` count and `remainingValues = max(0, distinctValues - len(values))`. `remainingKeys = max(0, totalKeys - len(keys))`.

    Median: `ROW_NUMBER() OVER (PARTITION BY key ORDER BY number_value)` and `COUNT(*) OVER (PARTITION BY key)` filtered to `position IN ((total + 1) / 2, (total + 2) / 2)`, then average the one or two rows in Python with `/ 2.0`. Integer division is load-bearing; do not replace it with `AVG`.

    `skippedKeys` counts `document_metadata_skips` rows joined to the eligible region; only documents in scope count.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → `metadata` tool inputs | Untrusted filter/match JSON plus window sizes. |
| typed store → discovery aggregates | Discovery must not read a different source than the compiler. |
| discovery output → MCP/CLI text | Machine output must stay clean. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-01 | Tampering | discovery SQL (filters, match, windows) | critical | mitigate | Every operand and window size is a bound parameter; key/value placeholders come from `?, ` lists. `compile_filter`/`compile_match` are the only predicate producers. |
| T-20-04 | Denial of service | huge value sets | high | mitigate | Key window (`limit`, default 50) and per-type value window (`value_limit`, default 10) with exact remainders; aggregates batched to the page's keys; no unbounded mode is exposed. |
| T-20-06 | Integrity | CLI/MCP output | medium | mitigate | JSON mode emits only the envelope; table mode emits only the table plus the remainder footer; no notice or warning enters either. |
| T-20-07 | Information disclosure | filter-aware denominators | high | mitigate | `documents` is the scope denominator and `filteredDocuments` is present only when a filter is supplied; skipped keys are counted, never listed as filterable. |
| T-20-SC | Tampering | package installs | high | mitigate | No dependency added; no install task in this plan. |
