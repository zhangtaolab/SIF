  <name>Task 3: Verdict review and evidence application — defaults only on an authorized win</name>
  <decision>Which measured outcomes authorize a shipped default change: chunk, breadcrumb, both, or neither?</decision>
  <context>
    Read both committed artifacts. The chunk artifact authorizes a chunk-default change only when `decision` is `adopt-chunking`, which requires a strict held-out winner beyond the 0.01 tie rule and above the strict 1/N floor for the tuning-selected non-baseline arm. The breadcrumb artifact authorizes an `embed_breadcrumb` default flip only when `decision` is `adopt-breadcrumb`, which additionally requires the body leg to win rather than a title-leg-only gain. With held-out N=56, the strict 1/N floor is about 0.0179, so a nominal 0.01 win is not reachable; `keep-default`, `keep-breadcrumb-off`, and `insufficient-evidence` are expected and are first-class outcomes. The offered option set is therefore usually keep-defaults; an adopt-* option is offered only when the corresponding artifact decision is adopt-chunking or adopt-breadcrumb.

    A chunk default change is costly: it changes the index layout and requires `sif index embed --force` on existing indexes. A breadcrumb flip is costly too: it changes the chunk embed contract and cache keys. Neither is one-way because the constants or the boolean can be reverted, but a published release is not undoable.
  </context>
  <options>

      <pros>Publishes both measured wins; the marker and docs record the new contract. Only offered when the chunk artifact is adopt-chunking and the breadcrumb artifact is adopt-breadcrumb.</pros>
      <cons>Requires re-embedding existing indexes twice over if both contracts change; largest documentation churn.</cons>
