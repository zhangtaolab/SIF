### Locked Decisions

#### Held-out-gated chunk sweep (QUAL-02)
- **D-01:** **Sweep arms are isolated file-backed indexes, one per chunk configuration, each built by a full re-chunk + re-embed.** Fix the embedder to Qwen3-Embedding-0.6B (Phase 23's keep-qwen3 verdict), the parser, the hybrid weights, and the title-FTS behavior; vary only `chunk_size`/`chunk_overlap`. The grid must include the current default (512/128) and stay small (target ≤6 arms; research/planner may refine the exact sizes/overlaps). Report per-arm documents/chunks/vectors, embed wall time, and cache deltas. — **Reversibility:** costly — the grid defines the evidence set for any default change.
- **D-02:** **Use the Phase 23 curated bilingual subset as the controlled corpus and its Qwen3 saved run as the baseline.** The subset (7 Chinese-heavy folders, 498 docs, adequacy en=42/zh=11, held-out N=56) is already the phase's evidence corpus; keeping the embedder and corpus fixed isolates the chunking effect. Record the `N=56 < 101` limitation: a 0.01 win is not admissible; the strict 1/N floor applies. If a larger corpus is supplied, it may replace the subset, but the same Phase 18 gate runs. — **Reversibility:** reversible — evidence can be re-run on a larger corpus.
- **D-03:** **A chunk-default change requires the Phase 18 held-out gate.** Use the paired bootstrap 95% CI + mean Δ ≥ 0.01 + the strict 1/N noise floor; a no-win is recorded with numbers and leaves the default unchanged. Commit a sweep artifact (e.g. `.planning/phases/24-…/bench/chunk-sweep.json`) plus a `docs/benchmarking.md` section with per-arm metrics and the verdict. No ad-hoc or in-sample default change. — **Reversibility:** costly — the published chunking default changes the index layout and re-embed cost.

#### Title-breadcrumb experiment (QUAL-03)
- **D-04:** **One breadcrumb arm vs the baseline, per-leg ablation, duplicate-signal check.** Breadcrumb = prepend the document's heading path (H1/H2 chain) to each chunk's *embedding text* only (stored content unchanged); title FTS and BM25 stay as-is. - **D-05:** **No breadcrumb default without a held-out win.** If the breadcrumb duplicates the title signal or fails the gate, record the rejection with numbers and keep the current chunk embedding unchanged. — **Reversibility:** reversible — evidence-only outcome.

## Summary

Phase 24 is three mostly independent workstreams that touch different seams: (1) an **offline tuning runbook** that reuses the Phase 18 instrument and the Phase 23 stage machine, (2) a **models command + cache contract** centered on `ModelDownloader`, and (3) **hand-written install docs** gated by the generator-owned CLI/config docs.

The single most important measurement in this research: **the live corpus is byte-identical to the Phase 23 corpus** — 498 documents, 0 path/checksum differences, corpus fingerprint `b5d50ce0c696ab3d` — so the Phase 23 Qwen3 saved run is directly reusable, and a fresh baseline would deterministically reproduce the same query set (assuming the corpus is unchanged at execution time). The Phase 23 scratch DBs are 200 MB each and the Qwen3 embedding cache already holds the 512/128 chunk texts, so the baseline sweep arm should be nearly free; only the *new* chunk configurations pay embedding cost.

The second key finding is a **validity constraint on the chunk grid**: `Settings.max_tokens` (default 512) is applied as the embedder's `max_seq_length` [VERIFIED: src/sif/embedding/embedder.py:170-171, 538-539], while `chunk_size`/`chunk_overlap` are tokens converted at **4 characters per token** for a character-based chunker [VERIFIED: src/sif/indexing/chunker.py:15-20; src/sif/cli/commands/index.py:399-403]. On this Chinese-heavy corpus the real ratio is ~3.41 chars/token, so at the shipped 512/128 setting **33.8% of chunks exceed 512 model tokens and 18.1% of embedded token volume is truncated**. Arms above 512 tokens would therefore be confounded (the vector sees only a prefix); the grid should stay ≤512 tokens.

The third key finding is that a literal **H1/H2 breadcrumb is mostly title duplication**: 467/498 documents have an H1 identical to the document title and 21,397/21,798 (98.2%) chunks come from those documents; but heading levels are unreliable in this corpus (8,538 H1 headings across 498 documents — scientific articles use H1 per section). A robust title-seeded breadcrumb gives every chunk a path, but its only genuinely new lexical content is the section heading for the 45.9% of chunks that are sub-chunks without a heading. The duplicate check must therefore be per-leg (body/long, not just title) plus analytical overlap metrics.

The fourth key finding is the **models bug surface**: `DEFAULT_MODELS` still names the 7B `iic/gte_Qwen2-7B-instruct` family [VERIFIED: src/sif/models/download.py:18-33], and the cache check computes `<cache>/<md5>` [VERIFIED: src/sif/models/download.py:69-75] — a directory ModelScope never writes. The real layout is `<cache>/<owner>/<name___>` (dots replaced) with `.msc/.mdl/.mv` metadata; `~/.sif/models` is only the `cache_embeddings=False` / legacy `sif pull` path. ModelScope 1.36.0 accepts only branch/tag revisions, and `Qwen/Qwen3-Embedding-0.6B` has **no tags** on ModelScope — so "deterministic revision" must mean a pinned branch plus a local SHA-256 manifest, not an immutable commit pin.

The fifth key finding is that the README's CPU-torch paragraph is **misleading for the primary install path**: `[tool.uv.sources]` in `pyproject.toml` applies to project/source installs, not to `uv tool install docsif[embed]` from PyPI; on Linux the PyPI `torch` wheel is CUDA-enabled. The honest uv-first recipe is `uv tool install --torch-backend=cpu 'docsif[embed]'` (flag present on local uv 0.13.7; support in `uv tool` added in uv 0.9.19 per the official changelog).

**Primary recommendation:** Run a 6-arm sweep capped at 512 tokens (`512/128`, `512/64`, `512/0`, `448/112`, `384/96`, `256/64`) through a Phase-23-style isolated-DB runbook, select any candidate on the tuning split and confirm it on the held-out gate; run one title-seeded breadcrumb arm (512/128, embed-text only) with per-leg + duplicate metrics; fix the model cache with a canonical `<Settings.get_cache_dir()>/models/<owner>/<name>` path, an atomic temp-dir download and a SHA-256 manifest; and rewrite installation docs around the verified uv recipe and a degradation matrix, regenerating the two generator-owned docs.

### Recommended chunk grid and cost (measured on the Phase 23 chunk set)

The grid stays at or below the 512-token `max_tokens` cap (see Pitfall 2) and includes the shipped default. “New embeds” assumes the Phase 23 Qwen3 cache is present, arms run sequentially, and identical chunk texts are reused.

Add ~5–10 minutes for indexing/model-load/eval; the breadcrumb arm adds ~22 minutes (its embed text is new, so ~full cost). If the cache was cleared, add ~22 minutes for the baseline. Source: measured this session against `.planning/tmp/phase-23-zh-heavy/qwen3.db`; cost scaling from `.planning/phases/23-harrier-gated-evaluation/bench/harrier-verdict.json` (`embed_wall_seconds: 1328.186`, `chunks: 21798`).

### Pattern 1: Isolated-arm tuning runbook (Phase 23 template)

### Pattern 2: Breadcrumb as an embed-text-only overlay

**What:** Build a parallel list of embedding inputs from `doc.title` + the chunk’s section heading; pass those to `EmbeddingManager.embed_documents`; keep `document_chunks.content` (and therefore `chunks_fts`, snippets, and BM25) byte-identical.

**When to use:** QUAL-03 only. Default off; one arm enabled by env.

**Implementation seam:** `StreamingEmbedWriter.embed_document` currently embeds `[chunk.content for chunk in batch]` [VERIFIED: src/sif/indexing/embed_writer.py:185] and persists `chunk.content` via the chunk repository [VERIFIED: src/sif/indexing/embed_writer.py:215-225]. `DocumentChunk` has no heading path field [VERIFIED: src/sif/core/models.py:162-186], and `MarkdownChunker.chunk(text)` receives only document text [VERIFIED: src/sif/indexing/chunker.py:106-148]. So the builder must derive the path from the ordered chunk sequence + `doc.title`, not from `start_pos` (sub-chunks of oversized sections have positions relative to the section, not the document [VERIFIED: src/sif/indexing/chunker.py:128-136]).

```python
# Sketch: pure, testable, no storage change.
def breadcrumb_embed_texts(title: str, chunks: list[DocumentChunk]) -> list[str]:
    out: list[str] = []
    current_section: str | None = None
    for chunk in chunks:
        first = chunk.content.splitlines()[0] if chunk.content.splitlines() else ""
        m = _HEADING_RE.match(first)  # ^(#{1,6})\s+(.+?)\s*$
        if m:
            current_section = m.group(2).strip()
        parts = [title.strip()] if title and title.strip() else []
        if current_section and current_section != title.strip():
            parts.append(current_section)
        path = " > ".join(parts)
        out.append(f"{path}\n\n{chunk.content}" if path else chunk.content)
    return out
```

**Cache consequence:** the cache key is `sha256(content)` + model bucket [VERIFIED: src/sif/embedding/cache.py:87-96; src/sif/embedding/manager.py:245-257], so the breadcrumb text is a different key from plain text — no collision, but almost no cross-arm cache hits. **Identity consequence:** `EmbedderIdentity` has no chunk/embed-text field [VERIFIED: src/sif/embedding/identity.py:118-150], so the breadcrumb arm must be an isolated DB; enabling it on an existing index without `--force` would mix plain and breadcrumb vectors under the same identity.

### Anti-Patterns to Avoid

- **Re-chunking in place by editing rows:** use `index embed --force`; the streaming writer’s delete-before-insert is the correctness contract.
- **Comparing two chunk arms in one DB:** one vec0 table is one vector space; chunk config is not in the identity, so mixed vectors are silently accepted.
- **Using `start_pos` for breadcrumb mapping:** sub-chunk positions are section-relative, not document-relative.
- **Treating a non-empty model directory as cached:** the current md5 bug; require a manifest/hash.
- **Hand-editing `docs/cli-reference.md` / `docs/configuration.md`:** regenerate.
- **Emitting Rich tables/spinners into a pipe:** non-TTY status/pull must be plain/JSON.
- **Changing the embedder load path to a canonical local path without a parity test:** the stored identity `revision` can change and break the Phase 23 baseline.

## Common Pitfalls

### Pitfall 1: Chunk settings are not persisted; a plain re-embed applies nothing
**What goes wrong:** A user (or the runbook) changes `SIF_CHUNK_SIZE`/`SIF_CHUNK_OVERLAP` and runs `sif index embed`; every document is reported “Already embedded” because `_needs_embedding` compares the **existing** chunk ids with the embedded chunk ids [VERIFIED: src/sif/cli/commands/index.py:200-207, 426-434].
**Why it happens:** Chunking config is not stored anywhere in the index; only the chunks themselves exist. `index update` does not chunk at all (chunking happens in `embed_cmd`).
**How to avoid:** Use `sif index embed --force` for every arm; never `index update --force` alone. Document the `--force` requirement wherever chunk settings are described. Optionally persist a `chunking.contract` `index_meta` marker (open question) so status can warn.
**Warning signs:** “Already embedded” for every document after a settings change; chunk counts unchanged.

### Pitfall 2: Arms above 512 tokens are truncated and confounded
**What goes wrong:** `Settings.max_tokens` (512) is assigned to `model.max_seq_length` [VERIFIED: src/sif/embedding/embedder.py:170-171, 538-539], so a 768- or 1024-token chunk is embedded from its first 512 tokens while the stored chunk/snippet contains the whole text.
**Why it happens:** The chunker converts tokens to characters at 4 chars/token [VERIFIED: src/sif/indexing/chunker.py:15-20], an English approximation; Chinese text averages ~3.41 chars/token on this corpus (measured). At 512/128, 33.8% of chunks exceed 512 tokens and 18.1% of embedded tokens are truncated (measured with the Qwen3 tokenizer).
**How to avoid:** Keep `SIF_MAX_TOKENS=512` fixed and cap the sweep at 512 tokens. Record the per-arm over-512 chunk share and truncated token share in the artifact. Do not raise `max_tokens` mid-sweep (it is not in the cache key — see Pitfall 3).
**Warning signs:** An arm’s nDCG changes but the chunk boundaries barely do; large chunks with long tails; an unexplained win for larger sizes.

### Pitfall 3: The embedding cache key does not include `max_tokens`, chunk config, or the breadcrumb mode
**What goes wrong:** The cache key is `sha256(content)` + model bucket (model id + revision + role prompt) [VERIFIED: src/sif/embedding/cache.py:87-96; src/sif/embedding/manager.py:245-257]. Two runs with different `max_tokens` but identical chunk text share a cache entry, silently returning the other run’s truncated vector.
**Why it happens:** Vector identity is model-level; generation parameters are assumed constant.
**How to avoid:** Hold `max_tokens` fixed at 512 across all arms; use a fresh DB per arm; for breadcrumbs, the embed text differs (so the key differs); if a future run raises `max_tokens`, use a separate cache dir or clear the bucket. Record the cache DB path and per-arm cache deltas.
**Warning signs:** An arm embeds suspiciously fast with a high cache-hit count despite a changed embed contract.

### Pitfall 4: The embedder identity does not capture chunking or breadcrumb contracts
**What goes wrong:** `EmbedderIdentity` fields are schema/cache_model_id/model name/type/api_base/dimension/pooling/normalized/prompts/revision [VERIFIED: src/sif/embedding/identity.py:118-150] — no chunk size/overlap/embed-text mode. Reusing a DB with a new chunking or breadcrumb mode leaves a same-identity index holding two embedding contracts.
**Why it happens:** The identity was designed for model swaps (EMB-01), not indexing-contract swaps.
**How to avoid:** One fresh DB per arm; never reuse the Phase 23 arm DBs for a new chunk config; if a breadcrumb/chunk default ships, require `index embed --force` and document the contract change. Consider an `index_meta` marker only if a default flips.
**Warning signs:** An arm DB's identity matches, but its vectors came from a different chunking; search quality looks inexplicably mixed.

### Pitfall 5: The H1 breadcrumb duplicates the already-indexed title
**What goes wrong:** A literal H1/H2 breadcrumb prepends the title to nearly every chunk even though `documents_fts(title)` already indexes the title [VERIFIED: src/sif/database/schema.py:540-550; src/sif/search/bm25.py:22-25]. A gain concentrated on the title leg is not new information.
**Why it happens:** 467/498 documents have an H1 identical to their title; 21,397/21,798 chunks come from those documents (measured). Heading levels are unreliable: 8,538 H1 headings across 498 documents, so literal level-stacking gives the title as path[0] for only 2,420 chunks (11.2%).
**How to avoid:** Use a title-seeded path (title + most recent heading of any level), report per-leg and per-length gates, and record analytical duplicate metrics (title share; section heading already in chunk content: 54.5%; sub-chunks without a heading: 45.9%). Reject if the body leg does not improve or if gains are title-leg-only.
**Warning signs:** Title-leg delta positive, body-leg delta flat/negative; breadcrumb text already present in the chunk content.

### Pitfall 6: The md5 cache check never hits and blesses junk
**What goes wrong:** `ModelDownloader.download` computes `<cache>/<md5(model_id)[:8]>` and treats a non-empty directory as cached [VERIFIED: src/sif/models/download.py:69-75]. ModelScope never writes that directory — with `cache_dir` it writes `<cache>/<owner>/<name___>` [VERIFIED: modelscope 1.36.0 `_snapshot_download`], so the check usually misses; if a user happens to create the md5 dir, any non-empty contents are accepted as a valid model.
**Why it happens:** The code conflates a directory-name convention with a content-validity check.
**How to avoid:** Compute the canonical model dir from the model id, require a manifest + per-file SHA-256, and re-download when the manifest is missing/corrupt. Keep `--force` as the explicit refresh.
**Warning signs:** Every `download()` re-invokes ModelScope despite a populated cache; a “cached” model directory with no weights.

### Pitfall 7: ModelScope cannot pin an immutable commit for these models
**What goes wrong:** `revision` is validated against branches/tags [VERIFIED: modelscope 1.36.0 `HubApi.get_valid_revision_detail`], and Qwen3-Embedding-0.6B/Qwen3-Reranker-0.6B/Qwen2.5-0.5B-Instruct have **no tags** — only `master` and PR branches [VERIFIED: ModelScope API query this session]. A “pinned revision” of `master` can move.
**Why it happens:** ModelScope’s hub does not expose commit-hash snapshots through `snapshot_download`.
**How to avoid:** Pin `revision="master"` explicitly in the registry, record the resolved revision from `.mv` and the per-file hashes in the manifest, and verify the manifest before reuse. Document that determinism is local-content determinism, not upstream immutability. Do not claim an immutable pin.
**Warning signs:** A pull one day resolves different weights with the same requested model id; no manifest diff is recorded.

### Pitfall 8: Generator-owned docs and manual SECTIONS
**What goes wrong:** Adding a Settings field or command without updating `scripts/generate_config_ref.py` `SECTIONS` or regenerating `docs/*.md` fails the CI diff gate or silently omits the field.
**Why it happens:** The config generator iterates a hand-maintained section list [VERIFIED: scripts/generate_config_ref.py:150-208, 292]; the CLI generator traverses the Click tree but does not skip hidden commands/options [VERIFIED: scripts/generate_cli_ref.py:90-124].
**How to avoid:** Every new command/setting: run `make docs-generate`, commit the regenerated docs, and run `pytest tests/test_docs.py`. Add hidden-command handling if `sif pull` becomes hidden.
**Warning signs:** `docs-validation` CI fails at `git diff --exit-code`; a new setting is missing from `docs/configuration.md`.

### Pitfall 9: Non-TTY output pollution
**What goes wrong:** ModelScope prints download progress to stdout; Rich tables/spinners can emit control/box characters into a pipe; a `--json` consumer breaks.
**Why it happens:** Library output is not TTY-aware; module-level Rich consoles are constructed at import.
**How to avoid:** `sif models pull` suppresses library output (wrap `snapshot_download` in `suppress_output()` or set quiet) and prints concise SIF lines; `sif models status` checks `sys.stdout.isatty()`, uses `click.echo` plain/JSON in non-TTY, and a Rich table only in a TTY. Deprecation notices go to stderr.
**Warning signs:** JSON parse errors when piping `sif models status --json`; escape sequences in captured output.

### Pitfall 10: Multi-arm selection is a multiple-comparison problem
**What goes wrong:** Picking the best of 6 arms on the held-out split and applying the single-comparison 0.01 gate inflates the false-winner rate.
**Why it happens:** The gate was designed for a pre-specified two-arm comparison.
**How to avoid:** Select the candidate on the tuning split (diagnostic), then apply the gate to that single candidate on the held-out split; report all arms’ gates as diagnostic. Record the selection rule in the artifact.
**Warning signs:** The “winner” changes when the grid changes; a marginal held-out result that only wins because it was chosen post hoc.

### Pitfall 11: Corpus drift or a missing Phase 23 scratch
**What goes wrong:** `--compare` refuses a corpus-fingerprint mismatch [VERIFIED: src/sif/search/personal_bench.py:2162-2179]; the Phase 23 saved run lives in gitignored scratch and may be deleted.
**Why it happens:** The corpus is the user’s live SynologyDrive; the scratch is disposable.
**How to avoid:** The runbook verifies the live fingerprint (`b5d50ce0c696ab3d` this session) and, if the saved run is missing or the fingerprint differs, runs a fresh baseline eval on the 512/128 arm with `--require-language en --require-language zh`, asserts the query-set fingerprint (`b71a4be84d2a8724` when unchanged), and uses that as the baseline. Record the baseline source.
**Warning signs:** Fingerprint mismatch; query-set fingerprint differs; missing saved-run file.

### Pitfall 12: Scratch growth and cleanup safety
**What goes wrong:** Each 1024-dim arm DB is ~200 MB (Phase 23 observed); six arms plus a breadcrumb arm ≈ 1.4 GB. Cleanup could delete user files if the scratch root is wrong.
**Why it happens:** SQLite + vec0 storage per arm.
**How to avoid:** Use a gitignored scratch subdir, reuse `assert_within_scratch`/`cleanup_arms` guards [VERIFIED: scripts/harrier_eval.py:1041-1084], and keep the embedding cache (useful) while deleting arm DBs.
**Warning signs:** Scratch under `~`; cleanup resolving outside the scratch root.

### Pitfall 13: llama-cpp wheels and the uv index strategy
**What goes wrong:** `docsif[all]` on Python 3.13 may build llama-cpp-python from source (official prebuilt wheels list Python 3.10–3.12); `uv tool install` may prefer PyPI’s sdist over the official wheel index under the default `first-index` strategy.
**Why it happens:** Wheel availability per Python/backend; uv multi-index resolution.
**How to avoid:** Document the official wheel index URL and the `--index`/`--index-strategy unsafe-best-match` recipe (flagged `[ASSUMED]` until verified), the source-build `CMAKE_ARGS` fallback, and Python 3.12 as the safe `[all]` path. Keep this a docs claim with a human verification checkpoint.
**Warning signs:** A long source build; missing `llama_cpp` after `[all]`.

### Pitfall 14: `sif pull`’s URL path has no timeout and no content check
**What goes wrong:** `request.urlretrieve` can hang, and the only validation is “file exists and is non-empty” [VERIFIED: src/sif/cli/commands/pull.py:27-37, 108-109].
**Why it happens:** Legacy GGUF convenience path.
**How to avoid:** Route the legacy alias through the new `models pull` handler, keep the GGUF file path but add a timeout and (optionally) a SHA-256 when a hash is supplied; document the trust boundary.
**Warning signs:** A hung `sif pull`; a 0-byte or HTML error page saved as `.gguf`.

    manifest = json.loads((model_dir / ".sif-model.json").read_text())
    for rel, info in manifest["files"].items():
        p = model_dir / rel
        if not p.is_file() or p.stat().st_size != info["size"]:

## Open Questions

1. **Should `sif models pull` pre-warm sentence-transformers models in the canonical tree?**
   - What we know: `ModelDownloader` serves ModelScope (the shipped default) and the reranker; `SentenceTransformerEmbedder` loads by name from the HF cache layout under `<cache>` [VERIFIED: src/sif/embedding/embedder.py:154-170].
   - What's unclear: whether to make the embedder prefer a canonical local path (risks changing the identity `revision` and breaking the Phase 23 byte-identical baseline).
   - Recommendation: scope MODELS-01 to the `ModelDownloader`/ModelScope path + GGUF files; for ST models, either pre-warm the HF layout (`snapshot_download(cache_dir=<cache>)`) or document the limit. Do not change the identity-producing load path without a byte-identical parity test.

2. **Should the chunk/embed-text contract be persisted in `index_meta`?**
   - What we know: chunk config is not persisted; the identity does not include it.
   - What's unclear: whether a status warning is worth a new storage contract.
   - Recommendation: document the `--force` requirement now; add a `chunking.contract` marker only if a default flips (and then gate it with `make docs-generate`).

3. **Settings field vs hidden flag for breadcrumb mode.**
   - What we know: a Settings field flows through the docs generator (SECTIONS) and is testable via env; a hidden CLI flag is not filtered by the generator either.
   - What's unclear: whether a rejected experiment should leave a public knob.
   - Recommendation: `embed_breadcrumb: bool = False` (env `SIF_EMBED_BREADCRUMB`), labeled opt-in; it is the least surprising and most testable arm switch.

4. **`sif pull` hidden vs visible.**
   - What we know: the generator/tests do not skip hidden commands.
   - What's unclear: whether the extra generator/test change is worth it for one release.
   - Recommendation: hidden + skip-hidden in the generator/test (matches D-06); fallback: visible with “Deprecated” help text.

5. **`docs/models.md` vs a new model-management doc.**
   - Recommendation: add a `## Model Management` section to `docs/models.md` (D-10 names it), linking to `docs/mcp-server.md` for client snippets and `docs/installation.md` for install recipes.

6. **Grid choice: 448/112 vs 320/80 as the sixth arm.**
   - Recommendation: 448/112 (near-default size step) plus 512/64 and 512/0 (overlap ablation); 320/80 is redundant with 256/384 at this budget.

7. **Selection rule: tuning-select → held-out-confirm vs all-arms held-out comparison.**
   - Recommendation: tuning-select then held-out-confirm; report all arms’ gates as diagnostic. This respects the Phase 18 split design.

8. **Should `max_tokens` ever exceed 512?**
   - Recommendation: not in Phase 24. It is a separate embed-contract decision (cache key + truncation + identity parity), not a chunking knob.

### Applicable ASVS Categories

|---------------|---------|-----------------|

### Known Threat Patterns for this stack
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Model-cache tampering / partial download treated as valid | Tampering | Manifest + per-file SHA-256 + atomic temp-dir replace; `--force` to refresh. |
| Supply-chain model substitution (same name, different weights) | Tampering / Spoofing | Record resolved revision + file hashes in the manifest; compare on reuse; document that upstream `master` can move. |
| Path traversal via model spec or cache dir | Tampering | `Path(...).name` for URL basenames; resolve and confine writes to the cache root; refuse scratch roots `/`/home in runbook cleanup. |
| SSRF / arbitrary URL fetch via legacy `sif pull` | Information Disclosure | User-invoked local command; add a timeout and document “trust the URL you pass”; do not fetch URLs from index metadata. |
| Secret leakage in output | Information Disclosure | Never print `SIF_API_KEY`; `models status` shows only model/cache/identity fields. |
| Malicious pickle weights `.bin` | Elevation of Privilege | Prefer safetensors; docs warn that loading a model executes its format; no automatic model selection from untrusted metadata. |
| Disk exhaustion from a 1.2 GB model / 7 arm DBs | Denial of Service | Report sizes; runbook disk-headroom guard (`MIN_FREE_DISK_BYTES`); cleanup arm DBs. |
| Non-TTY terminal injection / log forging | Tampering | Plain output with `click.echo`; sanitize/escape user-derived cells in Rich tables (existing `escape` precedent). |
