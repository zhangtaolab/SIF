<objective>
Make rerank an explicit, bounded, opt-in behavior at the settings and CLI surface.

Purpose: Today rerank is silently ON by default with a Qwen3 model, and `candidate_limit` is a no-op whenever it exceeds `limit`, so cap and threshold have no user-facing controls. QUAL-05 needs the fast path to be genuinely free and the enabled path to be governed by a validated candidate cap and a relative threshold. This plan owns the configuration/CLI half; Plan 06 owns the runtime scoring and pipeline half.
Output: `SIF_RERANK_ENABLED` (default false) plus `--rerank`; `SIF_RERANK_CANDIDATE_LIMIT` (5-50) and `SIF_RERANK_RELATIVE_THRESHOLD` (0 < alpha <= 1) enforced by Pydantic; `-C` resolving from the setting (existing flag retained, RESEARCH A3 waiver); generated config and CLI docs regenerated.
</objective>
