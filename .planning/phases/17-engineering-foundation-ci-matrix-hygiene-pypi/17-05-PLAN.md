<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tagged tree -> published artifact | Whatever is committed at the tag becomes immutable on PyPI; version, README marker, and metadata are baked at build time. |
| GitHub Actions -> PyPI/TestPyPI (OIDC) | Publish jobs mint short-lived identity tokens scoped by GitHub environment; a mis-scoped token or environment mismatch is a release-integrity surface. |
| build job -> publish jobs | The artifact crosses a job boundary; rebuilding or substituting it changes what is published. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-15 | Spoofing | PyPI package/version identity | high | mitigate | `name = "docsif"` is fixed; build gate requires `v${_version.py}` to equal GITHUB_REF_NAME exactly; tests pin the single version literal and every derived surface. |
| T-17-16 | Tampering | artifact between build and publish | high | mitigate | Build once in the build job, upload-artifact@v7 (if-no-files-found: error), download into dist/ in each publish job; no `uv build` in publish jobs; a test forbids rebuilds. |
| T-17-17 | Elevation of Privilege | OIDC token scope | high | mitigate | Workflow-level permissions are `contents: read`; `id-token: write` is job-scoped to the two publish jobs only; environments `pypi`/`testpypi` scope which workflow may mint; no long-lived tokens or secrets. |
| T-17-18 | Repudiation | absent provenance | medium | mitigate | Attestations stay at the trusted-publishing default (enabled); plan 17-07 verifies them with pypi-attestations. |
| T-17-19 | Spoofing | TestPyPI vs PyPI confusion | medium | mitigate | Separate jobs, separate environments, separate repository URLs; skip-existing is TestPyPI-only; PyPI has no skip-existing. |
| T-17-SC-05 | Tampering | npm/pip/cargo installs | high | mitigate | No new package; the workflow installs only from the frozen lock and runs `uvx twine`/`uvx pypi-attestations` as ephemeral tools, not project dependencies. |
</threat_model>
