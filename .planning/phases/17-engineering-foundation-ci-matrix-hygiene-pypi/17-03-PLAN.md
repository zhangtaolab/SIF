<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request (untrusted code) -> Actions runner | A PR can execute arbitrary repository code in CI; secrets and write tokens must not be reachable. |
| third-party action -> workflow | setup-uv and checkout run with the workflow token; a floating tag is a supply-chain substitution surface. |
| workflow -> uv.lock -> installed environment | The lock decides exactly what runs in every cell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-07 | Information Disclosure | PR-triggered workflow | high | mitigate | `pull_request` (not `pull_request_target`), workflow-level `contents: read`, no `secrets.` references, no id-token; guards assert all four. |
| T-17-08 | Elevation of Privilege | workflow token | high | mitigate | Least privilege at workflow level; no `write` permission anywhere in this workflow; a guard forbids `id-token` and `--no-cov`-style credential surfaces. |
| T-17-09 | Tampering | third-party actions (checkout, setup-uv) | medium | mitigate | setup-uv pinned to the verified commit SHA with a version comment; checkout uses the current major; a guard rejects floating `setup-uv@v*`. |
| T-17-10 | Tampering | dependency install in CI | medium | mitigate | `uv sync --frozen` consumes the committed lock; `cache-dependency-glob: uv.lock` keys the cache to the lock; per-version cache suffix avoids cross-cell collisions. |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | CI installs only from the committed lock; no package install step names a package directly; any new name would require the package-legitimacy gate. |
</threat_model>
