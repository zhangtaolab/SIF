<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| package index -> build environment | `uv` fetches wheels from PyPI plus one extra index; a mis-scoped extra index is a dependency-confusion surface. |
| pyproject.toml -> uv.lock -> CI | The lock is the only resolver input CI trusts; a stale or wrong-source lock silently installs unintended packages. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-04 | Tampering | extra index `pytorch-cpu` (dependency confusion) | high | mitigate | `explicit = true` on the index so it serves only torch; the source is marker-scoped to Linux; tests guard the explicit flag and the marker; every other name resolves from PyPI. |
| T-17-05 | Tampering | uv.lock integrity | medium | mitigate | Relock in one commit with the pyproject change; `uv lock --check` and `uv sync --frozen --dry-run` gates; guards assert no nvidia/triton/black; the lock is committed (never gitignored). |
| T-17-06 | Supply Chain | floor changes (sentence-transformers, llama-cpp-python, torch) | low | mitigate | Floors are pre-existing locked deps; no first-time install and no new package names; the Package Legitimacy Audit marks them approved pre-existing deps. |
| T-17-SC-02 | Tampering | npm/pip/cargo installs | high | mitigate | No new package names are introduced; only floors and a direct torch declaration change. Any future new name requires the package-legitimacy gate. |
</threat_model>
