<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub OIDC -> PyPI publisher | The environment + workflow filename + repo + owner form the identity that PyPI trusts; a mismatch prevents minting or, worse, trusts the wrong workflow. |
| human UI action -> release pipeline | Publisher registration is outside git and outside API; a wrong field is discovered only at publish time. |
| branch push -> release commit | The tag must point at a commit whose CI evidence is known. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-20 | Spoofing | trusted-publisher identity mismatch | high | mitigate | Exact fields recorded in the checkpoint instructions (owner zhangtaolab, repo sif, workflow filename publish.yml, environments pypi/testpypi); environment names in publish.yml are guarded by tests; a mismatch fails the first OIDC mint in 17-07. |
| T-17-21 | Elevation of Privilege | environment token minting scope | medium | accept | D-15 locks tag-as-release-intent, so no required reviewers; the environment still restricts which workflow may mint. Residual risk: anyone who can push a v* tag can release — mitigated by repository write access control, documented here. |
| T-17-22 | Tampering | tagging an unverified or drifted commit | high | mitigate | Pre-tag gate requires a green matrix on HEAD and a source diff since the smoke limited to _version.py; tag is pushed only after the gate. |
| T-17-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install in this plan; the gate reads CI state and git only. |
