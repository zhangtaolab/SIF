## Adopted Malformed-Read Policy (RESEARCH Open Question 1)

An unparseable non-NULL expiry is a **cache miss in `get()` with the row left untouched** — a read must not trust an unreadable TTL, but only cleanup's retain-guarantee owns the row. Pinned in `test_get_malformed_expiry_misses_and_retains_row` (docstring names the adopted resolution) and in `get()`'s docstring. `get()` catches exactly `(ValueError, TypeError)` around the shared parse; `clear_expired()` catches exactly `(ValueError, TypeError)` and continues (WR-09 locked semantics preserved; all existing WR-09 tests pass unchanged).

## Decisions Made

- **Malformed-read policy (OQ1 adopted):** miss without deletion; `(ValueError, TypeError)` caught on both methods — documented where enforced (test + `get()` docstrings).
- **BLOB for the non-string expiry test:** `expires_at` has TEXT affinity, so the plan's example INTEGER coerces to `'12345'` (text) on insert and would exercise the already-caught ValueError path vacuously. A BLOB is the only non-string form the production DDL can store; it raises the TypeError the widened catch must handle (affinity behavior probe-verified before writing the test).
- **Pragma read seam:** per-connection settings are read on the cache's own factory-delegated connection (RESEARCH code-example shape); persisted WAL additionally via raw connect (see deviation below).
