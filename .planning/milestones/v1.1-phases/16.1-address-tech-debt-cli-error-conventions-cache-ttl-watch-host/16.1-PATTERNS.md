
**Module conventions** (from `src/sif/cli/formatters.py:1-3` and `src/sif/database/factory.py:26-37`): module docstring first; `from __future__ import annotations`; stdlib → third-party (`click`) → first-party (`sif`) import order; two blank lines after imports; full ty annotations. `Generator` comes from `collections.abc` (database.py:6).

**Load-bearing constraints (from RESEARCH, verified against code):**
- The opener must accept the caller's `Database` symbol (`database_cls: type[Database]`), NOT import-and-construct its own — every CLI test patches `sif.cli.commands.<module>.Database` (see Shared Patterns: Test Patch Seams).
- `Database.__init__` creates the parent directory (`database.py:19-20`: `self.db_path.parent.mkdir(parents=True, exist_ok=True)`), so the constructor call itself must be inside the `OSError` boundary — pass the class, never a pre-built instance.
- Connection is lazy until `init_schema()` (`database.py:24-37`); catch `sqlite3.Error`/`OSError` around construction + `init_schema()` only. Do NOT wrap the `yield` (D-04: no command-body catch-all). `with db:` still guarantees close (`database.py:56-62` `__enter__`/`__exit__`).
- Remedy message: DB path + original error + permissions/disk/corruption hint (D-03).
