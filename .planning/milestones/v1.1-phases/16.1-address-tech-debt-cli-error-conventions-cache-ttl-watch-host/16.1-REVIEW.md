## Summary

Reviewed the shared CLI database opener and all adopted call sites, the instant-based LLM-cache expiry parser, factory-backed embedding-cache connections, and the watcher/watch-host reconcile API and ordering. Cross-checked the called `Database` and `create_connection` implementations because the new helper's cleanup guarantee depends on them.

Four defects were reproduced or traced to concrete failing paths. The top-level CLI still creates the index parent before entering the new error boundary, so a common invalid-path failure escapes as a raw `FileExistsError`. Valid ISO expiry strings at datetime boundaries raise an uncaught `OverflowError` during UTC conversion in both cache read and cleanup paths. Connection setup can also bypass the promised explicit close, and cleanup still suppresses every `OperationalError` from embedding deletion rather than only the expected absent-table case.

The watcher changes preserve the required ordering and queue separation: MCP startup calls `start()` before `enqueue_reconcile()`, reconcile producers use the public method, and the stop sentinel/event-fold producers remain direct. No private watcher queue access remains in `watch_host.py`. The embedding cache delegates pragma configuration to the shared factory without copying the recipe.

Validation: `ruff check` on scoped source and focused tests passed; `ruff format --check src tests` passed (190 files); `ty check src/sif` passed; the full suite passed with 1586 passed, 1 skipped, and 95.17% coverage. The focused 157-test subset also had no test failures, but its command exited nonzero only because the repository-wide 90% coverage gate was applied to a subset run.

## Critical Issues

### CR-01: Group-level parent creation bypasses the shared CLI error boundary

**File:** `src/sif/cli/main.py:71-76`
**Issue:** The group callback eagerly runs `ctx.obj["index_path"].parent.mkdir(parents=True, exist_ok=True)` before any subcommand reaches `open_initialized_database()`. Consequently, the new constructor-`OSError` translation never runs for one of the exact failures it is intended to handle. Reproduced through the real group with `--index <regular-file>/sif.db index update`: the invocation exits with a captured `FileExistsError` and no Click error message; standalone execution produces a traceback instead of the remedy-bearing error. The helper unit test invokes the helper directly and therefore misses this end-to-end bypass.
**Fix:** Translate the group-level `OSError` as well, or remove the eager directory creation where it is not needed and let the database boundary own it. For lifecycle commands that still need the parent directory, wrap this operation explicitly:

```python
index_path = ctx.obj["index_path"]
try:
    index_path.parent.mkdir(parents=True, exist_ok=True)
except OSError as e:
    raise click.ClickException(
        f"Cannot create index directory at {index_path.parent}: {e}. "
        "Check the path and file permissions."
    ) from e
```

Add a full-`cli` regression test using a regular file as the parent; assert exit 1 with a rendered `Error:` and no raw `FileExistsError`/`Traceback`.

### CR-02: UTC conversion overflows escape both malformed-expiry policies

**File:** `src/sif/database/repositories.py:519-528, 562-568, 617-624`
**Issue:** `_expiry_instant()` calls `datetime.fromisoformat(value).astimezone(timezone.utc)`. Parsing can succeed while `astimezone()` raises `OverflowError` when an explicit offset takes the instant outside datetime's supported range. For example, `0001-01-01T00:00:00+14:00` raises `OverflowError: date value out of range`. Both `get()` and `clear_expired()` catch only `ValueError` and `TypeError`, so this stored value crashes a cache read and aborts cleanup instead of producing a miss and retaining the row as their contracts require. Both methods were reproduced raising `OverflowError` on a real SQLite row.
**Fix:** Treat conversion overflow as another unreadable-expiry case in both methods:

```python
try:
    expires = _expiry_instant(expires_at)
except (ValueError, TypeError, OverflowError):
    return None  # get(); use `continue` in clear_expired()
```

Add both lower- and upper-bound offset cases (for example `0001-01-01T00:00:00+14:00` and `9999-12-31T23:59:59-14:00`) to the `get()` and `clear_expired()` tests, asserting no exception and row retention.

## Warnings

### WR-01: Connection-setup failures cannot be explicitly closed by the new opener

**File:** `src/sif/cli/error_handling.py:48-55` (via `src/sif/database/database.py:24-29` and `src/sif/database/factory.py:56-71`)
**Issue:** The helper closes `db` after `init_schema()` fails, but `Database.connection` assigns `_connection` only after `create_connection()` returns. `create_connection()` opens SQLite and then performs row-factory assignment and several pragmas without cleanup. If any post-connect step raises, `_connection` remains `None`; `db.close()` therefore cannot close the just-opened handle. A probe that raises `sqlite3.OperationalError` from the first pragma produced the expected `ClickException` but the opened fake connection's `close()` was never called. CPython will often reclaim the local connection during unwinding, but that is garbage-collection-dependent and does not satisfy the boundary's explicit “every path closes the handle” guarantee, including on other Python implementations. The same factory path now backs `EmbeddingCache`.
**Fix:** Make the factory close its local connection on every setup failure, so all consumers inherit deterministic cleanup:

```python
conn = sqlite3.connect(
    str(db_path),
    timeout=5.0,
    isolation_level="IMMEDIATE",
    detect_types=sqlite3.PARSE_DECLTYPES,
    check_same_thread=False,
)
try:
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")
    conn.execute("PRAGMA busy_timeout = 5000")
    _set_wal_with_retry(
        conn,
        attempts=_WAL_RETRY_ATTEMPTS,
        backoff_s=_WAL_RETRY_BACKOFF_SECONDS,
    )
    conn.execute("PRAGMA synchronous = NORMAL")
    _load_sqlite_vec(conn)
except BaseException:
    conn.close()
    raise
return conn
```

Add a factory-level test whose connection double raises during a pragma and asserts `close()` exactly once, plus an opener test proving the real call chain rather than only a post-assignment `init_schema()` failure.

### WR-02: Cleanup suppresses unrelated embedding-delete database failures

**File:** `src/sif/cli/main.py:238-245`
**Issue:** The embedding cleanup catches every `sqlite3.OperationalError` and reports zero removed embeddings. The intended tolerated case is an unavailable/absent `document_embeddings` table, but the same handler also suppresses `no such column` from a drifted schema, locking/I/O failures, and other operational database errors. Cleanup can then commit the remaining work and print success while orphaned embeddings were never processed. Narrowing the outer handler does not help because this inner handler discards the error first.
**Fix:** Suppress only the recognized absent-virtual-table case and re-raise every other `OperationalError` so the outer `(sqlite3.Error, OSError)` boundary renders it:

```python
try:
    cursor = conn.execute("""
        DELETE FROM document_embeddings
        WHERE document_id NOT IN (SELECT id FROM documents)
    """)
    embeddings_removed = cursor.rowcount
except sqlite3.OperationalError as e:
    if "no such table" not in str(e).lower():
        raise
    embeddings_removed = 0
```

Prefer a dedicated capability/schema probe if the project already exposes one, rather than broad message matching. Add a regression using a malformed `document_embeddings` schema (or another non-absence `OperationalError`) and assert cleanup exits nonzero and rolls back rather than reporting success.
