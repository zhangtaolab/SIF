## Summary

This is a bounded tech-debt phase, not a feature or dependency phase. The implementation should make four surgical changes: centralize CLI database construction/schema initialization behind a known-exception boundary; parse LLM cache expiries into aware instants on `get()`; delegate embedding-cache connections to the existing factory; and expose only reconcile intent on `FileWatcher`. The ledger edits are part of the deliverable, not follow-up bookkeeping. [CITED: .planning/phases/16.1-address-tech-debt-cli-error-conventions-cache-ttl-watch-host/16.1-CONTEXT.md:20-53]

The main design constraint is test compatibility. Existing CLI tests patch each command module's `Database` symbol, so a shared opener in a new module must receive that symbol from the caller; moving construction into a helper that owns its own `Database` import would bypass those patches. The two vector constructor guards must also remain separate from `pipeline.search()` handling so a reranker `RuntimeError` does not acquire a misleading sqlite-vec installation hint. [VERIFIED: tests/unit/cli/test_search.py:990-1009 — `test_other_exceptions_propagate_uncaught` asserts `isinstance(result.exception, ValueError)`; tests/unit/cli/test_get.py:568-574 patches `sif.cli.commands.get.Database`.]

A real-SQLite probe at HEAD reproduced both TTL failure directions: under `Asia/Shanghai`, an expired naive-local row returned `'r'`; under `America/Phoenix`, a fresh naive-local row returned `None`. The plan should require both directional regressions, not only an aware-UTC test. [VERIFIED: local probe, 2026-11-12 — output `Asia/Shanghai expired ... get= 'r'` and `America/Phoenix fresh ... get= None`.]

**Primary recommendation:** implement a class-injected `open_initialized_database(index_path, Database)` context manager for all 30 CLI open/schema sites, two constructor-only vector guards, one shared aware-UTC expiry parser, direct `create_connection()` reuse, and `FileWatcher.enqueue_reconcile(collections)` with iterable input and private tuple construction.

### Pattern 1: Class-Injected Database Opening

**What:** one context manager covers both `Database(...)` (whose constructor creates the parent directory) and lazy `init_schema()`, while accepting the command module's patched `Database` symbol.

**When to use:** every current CLI `with Database(index_path) as db: db.init_schema()` pair, including the two already-wrapped `main.py` commands so the convention has one implementation.

```python
# Source: recommended design from src/sif/database/database.py:17-37 and existing test patch seams.
@contextmanager
def open_initialized_database(
    index_path: str | Path,
    database_cls: type[Database],
) -> Generator[Database, None, None]:
    """Open and initialize a CLI database, translating only foreseeable failures."""
    try:
        db = database_cls(index_path)
    except OSError as e:
        raise click.ClickException(_database_remedy(index_path, e)) from e

    with db:
        try:
            db.init_schema()
        except (sqlite3.Error, OSError) as e:
            raise click.ClickException(_database_remedy(index_path, e)) from e
        yield db
```

Call sites become `with open_initialized_database(index_path, Database) as db:`. Do **not** wrap the `yield` in the known-exception handler: the helper's contract is construction/schema initialization, not a blanket command-body boundary. [VERIFIED: src/sif/database/database.py:19-21 — constructor executes `self.db_path.parent.mkdir(parents=True, exist_ok=True)`; lines 24-37 — connection is lazy until `init_schema`.]

The remedy should include the resolved/user-supplied DB path, original error, and a compact permission/free-disk/corruption action. Unexpected `ValueError` and other programmer exceptions must propagate; the context manager still closes via `with db`. [CITED: https://click.palletsprojects.com/en/stable/exceptions/ — Click handles `ClickException` and propagates other exception types.]

When `status`/`cleanup` adopt the helper, remove or narrow their now-redundant broad outer `except Exception` handlers. Otherwise the helper's `ClickException` is caught and wrapped again, the existing Rich `console.print` adds an error to stdout, and unexpected bugs remain masked contrary to D-04. [VERIFIED: src/sif/cli/main.py:212-214,258-260 — both handlers currently print and then `raise click.ClickException(str(e)) from e`.]

### Pattern 2: One Expiry Parser, Two Consumers

**What:** parse the stored text once and convert to aware UTC. Naive values deliberately use `astimezone(timezone.utc)`, not `replace(tzinfo=timezone.utc)`.

```python
# Source: recommended extraction of src/sif/database/repositories.py:585-592.
def _expiry_instant(value: str) -> datetime:
    """Parse an expiry and interpret legacy naive values as system-local."""
    return datetime.fromisoformat(value).astimezone(timezone.utc)
```

`get()` must select `response, expires_at` by key without the current SQL expiry predicate, return `None` for missing/expired rows, and return the response for NULL or future expiries. `clear_expired()` catches parse failure and continues, preserving its no-deletion guarantee. [VERIFIED: src/sif/database/repositories.py:529-535 — current predicate is exactly `AND (expires_at IS NULL OR expires_at > ?)`; lines 585-590 — current cleanup catches `ValueError` and `continue`s.]

Recommended malformed-read behavior: return a cache miss for an unparseable non-NULL expiry while leaving the row untouched. Cleanup and retrieval have different jobs: cleanup must not delete what it cannot interpret, but a read should not treat an unknown expiry as a valid cache entry. This is a planner-level recommendation because CONTEXT locks legacy/NULL cleanup behavior but does not explicitly lock malformed `get()` behavior.

Use `timezone.utc`, not the Python 3.11+ `datetime.UTC` alias, and do not add special `Z` parsing merely because the development interpreter supports it; the project supports Python 3.10. [CITED: https://docs.python.org/3/library/datetime.html — `fromisoformat` broadened in 3.11; naive `astimezone` presumes the system timezone.]

### Pattern 4: Intent-Only Reconcile API

```python
# Source: recommended encapsulation of src/sif/indexing/watcher.py:572,637.
def enqueue_reconcile(self, collections: Iterable[Collection]) -> None:
    """Queue one full reconcile per collection without exposing the job representation."""
    for collection in collections:
        self._queue.put((collection, FoldResult(needs_reconcile=True)))
```

Route `recovery_tick()` and `_schedule_added()` through this method with one-element iterables, and replace `_enqueue_startup_reconcile`'s loop with `watcher.enqueue_reconcile(collections)`. Remove `FoldResult` from the MCP host import and delete the `noqa: SLF001`. Preserve `watcher.start()` before the enqueue and never wait for reconcile completion in initialize/lifespan. [VERIFIED: src/sif/mcp/watch_host.py:40,92-100,154-157 — current import, private reach-in, and start/enqueue ordering.]

`queue.Queue` already provides the required FIFO/thread-safe mechanism; no new lock or executor is needed. Tests should use a quiesced worker and dequeue actual items rather than treating `qsize()` alone as an ordering proof. [CITED: https://docs.python.org/3/library/queue.html — FIFO, internal locking, and approximate `qsize()`.]

### Anti-Patterns to Avoid

- **Helper-owned `Database` import at call time:** bypasses command-module patches and turns mocked tests into real filesystem tests. Pass the symbol explicitly.
- **Wrapping the helper's `yield` in `except (sqlite3.Error, OSError)`:** converts unrelated later I/O failures into a DB-open remedy and broadens the locked scope.
- **One `RuntimeError` handler around construction plus search:** gives reranker/execution failures a sqlite-vec install hint. Separate the two stages.
- **CLI BM25 degradation:** forbidden for `vsearch` and not part of `query`'s fix; only the MCP boundary has that carve-out.
- **`replace(tzinfo=timezone.utc)` for naive legacy values:** relabels local wall time as UTC instead of converting the intended instant.
- **Deleting or rewriting legacy cache rows:** D-05 explicitly forbids migration/data rewrite.
- **Copying factory pragmas:** recreates W-1 under a different spelling.
- **Public generic job enqueue or public `FoldResult` construction in MCP:** exposes the protocol D-06 says to keep private.
- **Editing only source for finding closure:** ledger rows/counts would continue to report open debt.

## Common Pitfalls

### Pitfall 1: Shared Helper Breaks All Database Mocks
**What goes wrong:** commands call a helper that constructs its own imported `Database`; existing patches no longer intercept construction.
**Why it happens:** Python patch targets replace names in each command module, not the helper module.
**How to avoid:** pass `Database` as `database_cls` from every command and add a test proving the supplied class is constructed.
**Warning signs:** tests attempt real paths such as `MagicMock/exists/...`, unexpected SQLite files appear, or mock repository assertions stop being reached.

### Pitfall 2: Constructor OSError Escapes Before the Helper
**What goes wrong:** using `open_initialized_database(Database(index_path), ...)` leaves directory creation outside the boundary.
**Why it happens:** Python evaluates arguments before entering the helper; `Database.__init__` creates the parent directory.
**How to avoid:** pass the class, not an already-constructed instance.
**Warning signs:** permission-denied tests still return the original `OSError` in `result.exception`.

### Pitfall 3: Error Boundary Becomes a Catch-All
**What goes wrong:** `except Exception`, or known-class handlers around the whole command body, hides bugs or mislabels unrelated failures.
**Why it happens:** a context manager makes a broad boundary syntactically convenient.
**How to avoid:** restrict the helper to constructor/schema, restrict vector handling to constructors, and retain a test where `ValueError` propagates.
**Warning signs:** unexpected errors become exit-1 `ClickException`s with a DB or sqlite-vec remedy.

### Pitfall 4: Reranker Errors Get the Wrong Remedy
**What goes wrong:** moving `SearchPipeline(...)` into the existing `try` that also calls `pipeline.search()` and adding install text to that handler changes current reranker wording.
**Why it happens:** both stages raise `RuntimeError` for different reasons.
**How to avoid:** use a constructor-only handler with the sqlite-vec remedy and leave the execution handler as `ClickException(str(e))`.
**Warning signs:** the existing `Reranking failed` test gains sqlite-vec text.

### Pitfall 5: Aware Values Are Parsed Correctly but Legacy Values Are Relabeled
**What goes wrong:** naive local `09:00` becomes naive/aware `09:00+00:00` instead of the corresponding UTC instant.
**Why it happens:** `replace(tzinfo=...)` changes labeling, not timezone conversion.
**How to avoid:** use the cleanup's existing `astimezone(timezone.utc)` behavior and both east/west regressions.
**Warning signs:** only aware-UTC tests exist, or the tests pass in UTC but fail under a fixed non-UTC `TZ`.

### Pitfall 6: Unparseable Expiry Handling Diverges
**What goes wrong:** `get()` raises `ValueError`, serves malformed entries forever, or `clear_expired()` deletes them.
**Why it happens:** one helper is introduced without explicit malformed-row policy.
**How to avoid:** recommended `get()` miss plus `clear_expired()` skip; catch `TypeError` as well as `ValueError` for non-string stored values.
**Warning signs:** no test covers a garbage expiry on both methods.

### Pitfall 7: Existing Cache Failure Test Patches the Old Seam
**What goes wrong:** the W-1 test still describes itself as testing cache behavior but patches raw `sqlite3.connect` rather than proving factory delegation.
**Why it happens:** the old test was written against `sif.embedding.cache.sqlite3.connect`. [VERIFIED: tests/unit/embedding/test_cache.py:152-160 — `patch("sif.embedding.cache.sqlite3.connect", side_effect=OSError("connect failed"))`.]
**How to avoid:** patch `sif.embedding.cache.create_connection` for failure fallback and add a real factory/pragma assertion.
**Warning signs:** no mocked call to `create_connection`, or the test cannot tell raw connection code from delegation.

### Pitfall 8: Factory Hardening Accidentally Changes Cache Architecture
**What goes wrong:** the cache is moved into the main DB, its operations start raising, or pragma SQL is copied locally.
**Why it happens:** interpreting W-1 as a storage redesign instead of connection hardening.
**How to avoid:** change one acquisition line; rerun the existing corruption/fallback/segmentation battery.
**Warning signs:** edits to schema location, model segmentation, or the documented fallback return values.

### Pitfall 9: Public API Leaks the Job Tuple
**What goes wrong:** `enqueue_reconcile` accepts `FoldResult`, an arbitrary tuple, or a generic job; MCP still imports `FoldResult`.
**Why it happens:** lifting the current private call mechanically into a public signature.
**How to avoid:** accept only `Iterable[Collection]`; construct the tuple internally; route both internal producers through it too.
**Warning signs:** `FoldResult` remains in `watch_host.py`, or callers can enqueue burst/stop sentinels.

### Pitfall 10: Serve-First Becomes Index-First
**What goes wrong:** the host runs reconcile inline, waits on queue completion, or reorders startup around indexing.
**Why it happens:** confusing queue encapsulation with lifecycle redesign.
**How to avoid:** preserve `start()` then nonblocking enqueue and assert the indexer has not run before queue drain.
**Warning signs:** MCP initialize/lifespan latency depends on corpus size.

### Pitfall 11: Queue Test Relies Only on `qsize()`
**What goes wrong:** a size assertion cannot prove collection ordering or payload shape and is only approximate in general.
**Why it happens:** existing tests use `qsize()` as a convenient first assertion.
**How to avoid:** with a quiesced worker, dequeue with `get_nowait()`, assert collection order and `needs_reconcile`, then restore jobs if teardown must drain them.
**Warning signs:** no direct assertions on dequeued jobs.

### Pitfall 12: Ledger Closure Overclaims 15-IN-06
**What goes wrong:** IN-06 becomes `fixed` even though `_clear_history` still prints confirmation under `-q`.
**Why it happens:** the traceback half is fixed by the shared opener and looks like the whole row.
**How to avoid:** leave YAML `disposition: open` and `open: 6`; add partial-progress evidence to the Markdown Source cell only.
