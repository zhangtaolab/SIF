<objective>
Make the enabled rerank path bounded by a real candidate cap and a relative threshold.

Purpose: With rerank now opt-in (16-02), the enabled path must still be affordable: `candidate_limit` is currently a no-op whenever it exceeds `limit`, and there is no score threshold. QUAL-05 requires the cap to bind and the threshold to be applied relative to the top score, while the off path stays byte-identical.
Output: `SearchPipeline` over-fetches to `max(limit + offset, candidate_limit)` before slicing to the cap; `_sort_and_build_results` keeps candidates scoring `>= top1 * alpha` before `top_k` truncation; every reranker takes a `relative_threshold` kwarg (default 0.0, preserving direct construction) and `create_reranker` forwards the setting.
</objective>
