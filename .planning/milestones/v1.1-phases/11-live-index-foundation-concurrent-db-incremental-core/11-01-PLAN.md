## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem (user data dir) | lock file `{db_path}.lock` and WAL sidecar files are writable/visible to other local users on multi-user machines |
| concurrent processes → SQLite file | multiple SIF processes (CLI, MCP, future watch hosts) write one DB file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-01 | Tampering | src/sif/database/locking.py (lock-file creation) | medium | mitigate | Create the lock file exclusively via os.open(path, O_RDWR or O_CREAT, 0o600) next to the DB in the user data dir — a pre-existing world-writable file or symlink cannot be injected with write access; asserted by test_locking.py mode check |
| T-11-02 | Denial | index_lock wait loop | low | mitigate | Wait deadline (SIF_LOCK_WAIT_TIMEOUT, default 30s) bounds the pause; deadline expiry proceeds with the loser's own pass (D-02 availability-over-exclusion); the lock holds no data and is safe to delete when idle |
