<objective>
Close two Warning findings from the 2026-11-05 Phase-05 incremental code review (05-REVIEW.md, both "open" in 05-REVIEW-DISPOSITION.md):

1. **WR-03** — `context add` / `context remove` (src/sif/cli/commands/context.py) construct `Database(index_path)` + `db.init_schema()` without checking `index_path.exists()`, unlike sibling `context list` / `context prune` which guard and print "No index found.". `Database.__init__` mkdirs the parent and `sqlite3.connect` creates the file, so on a machine with no index these commands materialize a brand-new empty index DB as a side effect and report success ("Context added") for a context that can never attach.

2. **WR-09** — `Settings.reranker_model_type` has no field validator (only embedding `model_type` does), so `SIF_RERANKER_MODEL_TYPE=cross-encoder` reaches `create_reranker` (src/sif/search/rerank.py:429) which raises a plain ValueError that escapes query_cmd's `except ImportError` handling as a raw traceback — violating the CLAUDE.md ClickException convention.

Fix strategy (per task decision): WR-03 — replicate the exact sibling guard in add/remove, matching list/prune exit semantics (planner-verified: bare `return`, exit 0). WR-09 — preferred fail-early `field_validator` PLUS query_cmd catch as defense in depth; the validator's blast radius is contained by guarding the two settings-load points on the query path (`_get_default_db_path` in main.py for invocations without `--index`, query_cmd itself for invocations with `--index`).

Planner-verified facts this session (executor may rely on them):
- create_reranker has exactly ONE production call site: src/sif/cli/commands/search.py:506 (query_cmd). bench.py mentions "Reranker" only in a `--candidate-limit` help string (bench.py:28); src/sif/mcp/ has zero reranker references. No other call sites to cover.
- pydantic ValidationError subclasses ValueError.
- Existing factory tests (tests/unit/inference/test_reranker.py:287-335) build MagicMock settings, so the new Settings validator cannot break them; `test_create_reranker_unknown_type_raises` remains the direct probe of the factory ValueError that query_cmd's new except clause converts.
- Grepped baselines at HEAD: 'No index found' in context.py = 2; 'ValidationError' in main.py = 0 and in search.py = 0; 'except ValueError' in search.py = 0; no reranker_model_type validator in settings.py.
- Affected test files green at HEAD: test_context.py + test_settings.py = 33 passed; test_search.py = 24 passed; test_reranker.py = 27 passed.

Purpose: user-facing correctness — no silent empty-DB creation on fresh machines; invalid reranker config fails fast with a clean one-line error naming the field and allowed values.
Output: two guarded context commands, a validated reranker_model_type, clean ClickException surfacing on both query invocation paths, and seven regression tests.
