<objective>
Close UAT gap G-19-9 (UAT test 9; review item IN-10) under assumption A-19-9-1: `sif search query --min-score` keeps its behaviour, and every text a user reads says what that behaviour is.

The gap. The help text of `query` promised a minimum score threshold, but the displayed score of a hybrid row was never compared with it. `HybridSearcher.search` copies the caller's `min_score` into the fetch options of both legs, so one number is a floor on two different scales: the BM25 leg keeps matches whose displayed BM25 score is at least the value, and the vector leg keeps matches whose vector similarity is at least the value. A fused row's displayed score is an RRF value near 0.01 to 0.03, so with `--min-score 0.02` the page still held rows showing 0.0139; and when one leg returns nothing the page is that leg's, with its own scores. The gap predates the first round; plan 19-12 recorded it as out of scope and kept the help text on purpose (its prohibition 3 and its truth 8). This plan supersedes that prohibition for the `query` help text deliberately, under the gap.

Why this direction. Three directions were put to the operator: filter the fused score after fusion; keep the per-leg floor and describe it; hide the option on `query`. The orchestrator recommended the second and the operator ordered this planning after reading that recommendation without naming another direction. The plan is therefore written for the second and carries it as assumption A-19-9-1, which the operator confirmed on 2026-11-27. The two other directions need new plans.

What changes: text only, on five surfaces.
- The `--min-score` help text of `sif search query` says that each leg keeps matches scoring at least the value on its own scale, names the two scores, and says that the fused hybrid score of a result is never compared with it.
- The `--min-score` help text of `sif search vsearch` names the vector similarity it filters on. The orchestrator allowed this one-line change and the plan takes it: it closes review item R2-03 of the UI review in full, instead of half.
- `docs/cli-reference.md`, regenerated by `make docs-generate` and never by hand.
- `docs/mcp-server.md`: the `query` row and the `lex_search` and `vec_search` sentences, which listed `min_score` without saying which score it filters.
- `docs/changelog.md`: one new entry under `[Unreleased]`, which carries a correction. The entry plan 19-12 added ends by telling readers to convert a threshold written against the old scores by subtracting it from 1. That holds for `sif search search` only: the same number on `sif search query --min-score` is also the vector leg's threshold, which did not change. That entry was released in 1.2.4 with that sentence, and it stays as released: the operator decided on 2026-11-27 that entries under a released version heading are not edited, so the correction goes into the new entry and a gate proves the released sections unchanged.

The MCP wire is not touched. The MCP `query` tool publishes no description for `min_score`: its schema in all five wire goldens is default, minimum, title and type, and no parameter of any of the seven tools carries a description. Nothing on the wire was false, so there is nothing to correct there. Publishing a description would add a line to every locked `tools/list` golden, which is a change to a published contract that this gap does not need; it is a follow-up on the Phase 22 surface and is out of scope here. The plan carries that as a prohibition and proves it with a gate.

What stays open. R2-04, a four-decimal printed score passed back as `--min-score` can round above the row's exact score; and R2-01, the band in which a BM25 threshold bites is not discoverable.

Records superseded, unedited: the clause of plan 19-12's truth 8 that the `query` help text is kept, and its Task 3 gate 1, whose two counts this plan changes (the earlier wording twice becomes zero; the phrase about a stronger match once becomes three).

Reversibility. Two help strings, the rows a generator derives from them, and hand-written documentation; no behaviour, no schema and no stored data change, and a wording is changed back as easily as forward. Both tasks are rated `reversible` and neither carries a checkpoint. The operator's confirmation of A-19-9-1 on 2026-11-27 is the one decision this plan rests on.

Cascade. Executing this plan re-stales the verifications of Phases 17, 18, 20, 21, 22 and 24; all of them already read `stale` after the first round, and Phase 19 is re-verified after this round.

Decision coverage: keeps D-06 and the CONTEXT locked-upstream pagination rule untouched (no searcher changes) and implements no new CONTEXT decision; it makes the text of a Phase 19 option agree with the code that option runs.
