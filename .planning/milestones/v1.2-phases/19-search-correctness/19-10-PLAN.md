<objective>
Close UAT gap G-19-1 (UAT test 1) and the UAT test 3 decision row: make chunk identity survive every per-chunk output of `sif search query` and `sif search vsearch`.

G-19-1: at 80 columns 0 of 12 chunk rows showed `#sequence` in either per-chunk table, because Rich ellipsizes the tail of the narrow Chunk cell, which is exactly where the sequence lives. UAT test 3: `--csv`, `--md` and `--xml` carried chunk-level rows with no chunk field and `--files` printed a path once per chunk row.

Purpose: CONTEXT D-03 makes chunk identity part of the result contract (display form `path#sequence`, so a client can address the matched chunk). Plan 19-07 delivered it in the Rich table and JSON, but the table lost it at the canonical terminal width and the machine formats never carried it.

Assumption A-19-10-1 (UAT test 3), for plan review. UAT test 3 is a decision row: whether machine formats must carry chunk identity, and whether `--files` may repeat a path, is the operator's call. This plan is reviewed before anything executes, and the behaviour it implements for test 3 is an assumption the reviewer confirms or amends here, not a decision taken at execution time: chunk-level rows in CSV, Markdown and XML carry the identity in the `path#sequence` display form plus the bare sequence number in one field per format, a seventh CSV column named `sequence`, a `Sequence` line in Markdown and a `sequence` element in XML; `--files` and the quiet path-only output of per-chunk pages list each path once; document-level rows from the BM25 leg keep the plain path and get none of these fields; default (non-per-chunk) output does not change; adding the four options to `vsearch` is out of scope. The change is recorded in `docs/changelog.md`. A different choice re-plans the machine-format and path-only part of Task 2; the human-check on Task 2 still shows the operator the result.

Design (planner's choice; the gap allows its own column or suffix-preserving truncation): keep one `Chunk` column showing `path#sequence`, but make the cell size itself at render time. Rich hands each cell its real column width; the cell shortens the path from the left to fit that width and never drops the suffix. The column's floor is 8 display cells. Rich's table layout restores a column to its floor after sharing out the console width, so the floor decides whether the table still fits: with a floor of 24 the hybrid per-chunk table was 89 cells wide at 80 columns on this plan's own rows (87 and 94 with the Content column) and the terminal cropped the right border and the snippet tail. With a floor of 8 the column takes the share Rich gives it (15 cells in the hybrid layout at 80 columns, 37 in the vector layout, 10 and 17 with the Content column) and every per-chunk layout is exactly 80 cells wide. A separate narrow sequence column was rejected because it breaks the shipped assertion that the table displays `path#sequence`. The floor keeps the sequence visible; it cannot make a 15-cell tail name the document, which is why the first human-check asks whether rows stay recognisable.

Decision coverage: implements CONTEXT D-03 (chunk identity in per-chunk output; display form `path#sequence`) and keeps D-01 (no new option on document-level surfaces).

Output: a Chunk cell and column that survive an 80-column terminal without cropping the table, per-chunk identity in CSV, Markdown and XML, unique-path output for per-chunk pages, a changelog entry, and twenty-three new tests.
</objective>

|----------|-------------|
| indexed document paths and titles -> terminal, CSV, Markdown, XML | Document-derived text (file names and titles chosen by whoever wrote the files) crosses into every renderer |
