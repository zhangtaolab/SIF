<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI user -> filesystem | Vacuum/backup write to the index directory and a target path |
| backup target path -> host filesystem | A user-supplied path could overwrite or expose files |
| live readers/writers -> maintenance | Concurrent connections share the database during maintenance |
| disk capacity -> VACUUM | Vacuum needs temporary space |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-19 | Information Disclosure | backup output path | high | mitigate | CLI-only in this phase; refuse existing/symlink/DB/sidecar targets; create the default directory 0700, chmod the copy 0600 (Task 2). |
| T-21-20 | Tampering | VACUUM/backup against a live database | high | mitigate | flock + busy timeout + no open transaction + WAL checkpoint + official online backup API + integrity_check; busy errors are retryable, never partial success (Tasks 1-2). |
| T-21-21 | Denial of Service | disk exhaustion during VACUUM | medium | mitigate | Conservative 2x (db + WAL) precheck with required/available numbers before VACUUM (Task 1). |
| T-21-22 | Tampering | vacuously recreated shadow rows | low | mitigate | Reconcile joins `documents` on insert, so a deleted document is never resurrected (Tasks 1, 3). |
| T-21-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package install occurs in this phase; the legitimacy gate is a no-op. |

## Residual Risk

VACUUM's temporary database may live on `SQLITE_TMPDIR`, which can be a different filesystem from the DB. The precheck measures the DB directory as specified; a disk-full error from the temp volume is mapped to a remedy-bearing ClickException rather than prevented. Accepted.
</threat_model>
