<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Explicit-Qwen3 env → comparison | A wrong env would measure the wrong vector space and could hide a baseline change. |
| Comparison JSON → proof block | The proof is derived from an untrusted payload and written into the committed artifact. |
| Retained scratch data → proof run | The arm DB and saved run must be the exact pre-flip pairing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-20 | Tampering | Zero-delta acceptance | high | mitigate | Exact `== 0.0` on every overall/split/language/leg/leg-split delta; missing blocks are errors; no `approx` or tolerance. |
| T-23-21 | Spoofing | Explicit-Qwen3 env and pairing | high | mitigate | Build the env from the Qwen3 `ArmSpec` with prompt keys absent, reuse the same arm DB and pre-flip saved run, and require the corpus fingerprint check to pass. |
| T-23-22 | Repudiation | Proof provenance | medium | mitigate | The proof is written programmatically with the unchanged Qwen3 identity fingerprint and a timestamp; the artifact is committed so the block is auditable. |
| T-23-23 | Denial of service | Missing retained scratch data | low | mitigate | The mode exits 1 with the `--keep-arms` remedy before loading a model; the flip cannot be certified without the proof. |
| T-23-SC | Tampering | Package installs | high | mitigate | No package is installed by this plan; the Qwen3 model is cached locally. |
</threat_model>
