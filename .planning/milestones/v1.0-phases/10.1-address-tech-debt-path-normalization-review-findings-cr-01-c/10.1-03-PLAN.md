<objective>
Close Phase 10 review finding CR-02 (critical, open): `format_results_xml` escapes markup delimiters but passes XML-1.0-forbidden control characters through, producing output that downstream parsers reject as not well-formed (reproduced live in research: `ET.fromstring` raises ParseError on \x0b).

Fix shape (frozen spec, W3C XML 1.0 Char production): strip exactly #x00-#x08, #x0B, #x0C, #x0E-#x1F, surrogates #xD800-#xDFFF, #xFFFE-#xFFFF; keep #x09/#x0A/#x0D; do NOT strip #x7F-#x9F. Keep xml_escape/quoteattr (they correctly handle <>&'") — the sanitizer runs BEFORE them. This plan also converts search.py's three WR-01 Database sites so the file is wholly owned by one plan in Wave 1.

Purpose: machine consumers (agents piping `--xml`) always receive parseable output regardless of what control characters live in indexed content or the query.
Output: sanitizer + wiring in search.py; unit + round-trip tests; three lifecycle conversions with closure tests.
Spec-less probe fallback skipped: phase has no requirement IDs to probe (visible skip).
</objective>
