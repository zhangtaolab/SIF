- **Found during:** Task 3 verification
- **Issue:** The plan specifies two closure tests (search success, query pipeline-exception), both patching `sif.cli.commands.search.Database`. vsearch_cmd imports `Database` inside its function body, so a regression reverting ONLY vsearch to a raw construction would pass both plan-specified tests while violating the must-have truth ("search, query, and vsearch close their Database connection on success and on exception").

**2. [Rule 1 - Bug] Query closure test passed for the wrong reason**
- **Found during:** Task 3 follow-up (vsearch test development)
- **Issue:** `Database.init_schema()` resolves `get_settings` lazily per call, so the test's patched MagicMock settings fed a MagicMock `embedding_dim` into the real SchemaManager — vec0 DDL crashed with OperationalError inside the `with` block, which still closed the Database and satisfied `exit_code != 0`. The test could pass without ever reaching the intended pipeline RuntimeError path.
- **Fix:** Gave the patched settings a real `embedding_dim=4` (comment documents why) and asserted `"boom" in result.output` to pin the intended failure path. Same fix applied to the new vsearch test.
- **Files modified:** tests/unit/cli/test_search.py
- **Verification:** Closure tests pass with the pipeline error message present; init_schema completes for real.
- **Committed in:** 97fd2d7
