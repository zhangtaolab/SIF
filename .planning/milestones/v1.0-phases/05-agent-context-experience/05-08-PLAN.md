# Root cause (05-VERIFICATION.md gap 1 — read it in full before starting)

All four failed truths share one root cause. The SQL clause `target_id IN (<result paths>)` compares raw strings. A context stored as `/tmp/vault/doc.md` (verbatim user input — `context add` does no normalization) never matches a result path of `/private/tmp/vault/doc.md` (what `documents.path` stores, because indexing uses `Path(file_path).resolve()`). The SQL returns zero rows, so the downstream `os.path.realpath()` normalization in bm25.py:120-125, vector.py:127-132, hybrid.py:142-145 never receives any rows to normalize. It is dead code for exactly the scenario plan 05-06 was created to fix.

CRITICAL design constraint: **realpath is not invertible.** An IN-list built from result paths (or their normalized variants — which are identical, since result paths are already resolved) can NEVER contain the verbatim form of a stored legacy context row. Any exact-match SQL pre-filter reintroduces the bug. The correct read-side fix is a single batch query of all path-type contexts with normalization of both sides in Python. D-06's locked approach (Python-layer batch query, no SQL JOIN, no N+1) is preserved — only the broken pre-filter shape from D-06 step 3 is dropped, because 05-VERIFICATION.md identifies it as the root cause of the CTX-03 failure.

Related review findings this plan resolves as a side effect: IN-03 (triplicated `_attach_contexts` with a test-coupled MagicMock/tuple fallback in hybrid.py:127-141 that exists only to let mocked rows bypass row typing).
