<objective>
Close the write-side and prune halves of the 05-VERIFICATION.md root cause: store canonical path targets at `context add` time, self-heal legacy verbatim rows on re-add, and make `context prune` use the same normalization as search so it stops deleting valid contexts (REVIEW CR-02).

Purpose: `context add` stores the path target verbatim (context.py:58 — no expanduser/realpath), so `~/notes/a.md` and symlink-alias paths are stored unresolved; they never byte-match the resolved `documents.path`, become dead data in search, and — because `delete_orphaned_paths()` compares raw strings (repositories.py:437-444) — are then silently destroyed by `context prune` even though the document exists. 05-VERIFICATION reproduced this live.

Output: normalized `context add` write path with dual-form upsert self-heal; `ContextRepository.update_target()`; rewritten `delete_orphaned_paths()` using normalize_path; real-SQL prune tests in a new test file; CLI tests for the normalized write path.
</objective>
